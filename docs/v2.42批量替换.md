# v2.42：批量队列换成单模组流程

## 为什么换

旧批量（`src/localization/batch.py`）从游戏目录的 `.xl` 出发，只解 `.archive`
里的 CR2W 本地化，产物写输出目录。它有三个硬边界：

1. **看不到明文层**。`.reds` / `.lua` / 语言包 json 全部在 mod 目录里，不在归档里。
2. **候选池小**。staging 里 286 个 mod，只有 109 个带 `.xl`；历史探测缓存里实际
   识别出本地化资源的只有 74 个、2459 行。
3. **能力是另一套**。没有 undo、没有 soft/hard 失败分级、没有「标记为代码」，
   写回逻辑和单模组完全独立，修一处要改两遍。

单模组的 `_do_load` 早就是三层合并（语言包 / 源码 / 归档），只是它要求一个
**目录**。而 Vortex staging 里 286 个 mod 全是目录 —— 这对矛盾就是这次替换的入口。

## 实测差距

对 286 个 staging 目录跑单模组的明文层提取（`locale_pack.detect` +
`pick_sources` + `extract_root_ex`），33 秒，0 解析错误：

| | 旧批量 | 单模组流程 |
|---|---|---|
| 候选池 | 166 个 `.xl` | 286 个目录 |
| 有文本 | 74 个 / 2,459 行 | 101 个 / 16,126 行待翻 + 10,730 行已译 |
| 层 | 归档内嵌 | 语言包 + `.reds` + `.lua` + 归档 |

文件类型分布：153 个有 `.reds`、66 个有 `.lua`、164 个有 `.archive`、
41 个有语言包 `.json`、109 个有 `.xl`、28 个什么文本都没有。

## 新结构

```
src/mod_batch.py
  list_dirs(staging)        列出 staging 一级子目录
  probe_text(root, target)  预扫：只抽明文层，数出待翻 / 已译行数
  copy_mod(...)             复制到输出根，可跳过资产与归档
  Ctx / run / run_one       串行调度，逐 mod 复制 → load → translate → apply
```

`web_app.Api` 侧新增：

| 方法 | 作用 |
|---|---|
| `spawn_worker()` | 派生独立 `Api` 实例，静音 `_emit`，共享 memory/glossary/terms |
| `batch_scan(staging)` | 异步预扫，事件 `mb-scan` / `mb-scanned` |
| `batch_start(keys, with_archive, skip_assets)` | 异步跑队列 |
| `batch_cancel()` | 同时设 `_mb_cancel` 与当前 worker 的 `_stop` |
| `batch_info()` / `batch_results()` | 面板信息 / 上次结果 |
| `batch_open_output()` / `batch_clear()` | 打开、清空 `userdata\batch\out` |

### 为什么派生实例而不是重构

`_do_load` / `_run_translate` / `_do_apply` 本来就是**同步函数**，异步只发生在
`load_mod` / `translate` / `apply` 三个薄壳里。直接 new 一个 `Api` 绕开薄壳，
会话状态（`rows` / `root` / `meta` / `l10n_session` / `_stop` / `_busy`）天然隔离，
现有代码一行都不用动。

代价：批量里看不到每个 mod 的明细行，也改不了单条译文。要看明细就用单模组打开
`userdata\batch\out\<mod名>\`。真需要「批量里人工介入」时再做会话抽象（约 1500 行
搬移）。

## 复制规则

| 类别 | 默认 | 说明 |
|---|---|---|
| 语言包 / `.reds` / `.lua` / 配置 | 复制 | 翻译的目标 |
| 贴图 / 音频 / 视频 / 字体 | 跳过 | 不参与翻译，占九成体积 |
| `.archive` | 跳过（可勾选） | 纯归档汉化的 mod 需要它；勾了才复制 |
| `.git` | 跳过 | 不是 mod 内容 |

产物是**覆盖包**：目录结构与原 mod 一致，但缺资产文件。装进 Vortex 时按文件级
覆盖，缺的部分仍由原 mod 提供；卸载原 mod 后会留下孤儿文件。

体积：全部明文文件（2838 个 `.reds`/`.lua` + 87 个语言包 json）合计 78 MB；
101 个有文本的 mod 整目录合计 2.51 GB；归档 297 个共 9.93 GB（默认不复制）。

## 事件协议

| 事件 | 时机 | 字段 |
|---|---|---|
| `mb-scan` | 预扫每 5 个目录 | `done` / `total` / `name` |
| `mb-scanned` | 预扫结束 | `items` / `total` / `usable` / `rows` |
| `mb-start` | 开始 | `total` / `outRoot` |
| `mb-item` | 每 mod 开始 / 结束 | `phase` / `index` / `key` / `copied` / `todo` / `machine` / `applied` / `failed` / `errors` / `seconds` |
| `mb-done` | 全部结束 | `cancelled` / `results` |

## 实测（2026-11-01）

- 预扫 286 个目录：33.3 秒，101 个待翻，16,126 行，10,730 行已译，0 错误
- 单个 mod 端到端（`Car Modification Shop`，268 行）：
  复制 87 个文件 / 448 KB（跳过 1 个）→ load 268 行（121 语言包 + 147 源码）
  → 假译文 5 条 apply 成功，undo id `20261101-100032-9ee165ec`
- 语言包层的写回是「生成目标语言文件」，不改英文源文件。这条 mod 生成了
  `zh_CN.lua`，与它自带的 `zh-cn.lua` 并存 —— 见下。

## 已知问题（不在本次范围）

`TARGET_NAMES["zh-CN"]["lua"] = "zh_CN"`，但 staging 里 5 个模组用 `zh-cn.lua`、
0 个用 `zh_CN.lua`。CET 按 `require("localization/" .. language)` 加载，`language`
取自游戏设置（`zh-cn`），所以生成的 `zh_CN.lua` 读不到。`ChineseSimplified.reds`
命名正确（35 个），不受影响。

修法记在 `docs/backlog.md` 的「待办：单模组功能整体优化」。
