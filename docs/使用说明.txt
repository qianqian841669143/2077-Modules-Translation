====================================================
  赛博朋克 2077  模组翻译器  v2.23
====================================================

【这是什么】
  把 2077 模组里的可翻译文本提取出来, 在表格里逐条填中文,
  再一键写回模组的图形工具。适合把英文模组汉化, 也适合修改已有汉化。

  v1.1 支持三类文本来源:
    * REDscript (.reds)   —— 设置菜单 @runtimeProperty 里的文本
    * 输入 XML (.xml)
    * CET Lua (.lua)      —— Mod Settings / Native Settings UI / ImGui
                             注册的设置名称、描述、分类、选项、按钮标签
                             这是 v1.1 新增的重点功能

【v2.45.3 更新: 「跑完覆盖回原模组」勾了会真的生效】
  1. 批量面板的三个勾选(跑完覆盖回原模组 / 只预演不写 / 隐藏无需翻译)以前存不进
     设置文件 —— 白名单漏了这三个键, 前端发过来也被丢掉, 跑起来读到的永远是默认值
     (不覆盖、只预演)。表现就是: 勾了「跑完覆盖回原模组」, 跑完却只有输出目录里有
     译文, 安装缓存目录里一个字节没变。
  2. 现在勾上、点开始, 跑完会按文件覆盖回安装缓存目录里的那个模组(副本里没有的文件
     不动)。想先看会改哪些文件, 就保持「只预演不写」, 跑完看
     userdata\batch\deploy-<时间>.csv。

【v2.46.0 更新: 设置界面的「标题 + 描述」成对表也会翻; 单词不再误用官方译法】
  1. 有些模组的设置界面把每一项写成「短标题 + 说明」的一对, 例如
     bindToggle = { "Switch perspective", "在第一人称和第三人称之间切换。" }。
     以前只收走了较长的那一半(说明), 短标题永远进不了表格 —— 界面上就是
     「说明是中文、标题还是英文」。现在这种成对的表整片提取: 标题按「显示名称」、
     说明按「描述」列出来。实测 Immersive Third Person 从 6 行变 131 行。
     数据表(色值 / 记录名 / 事件名)仍然不提取。
  2. 只用于日志的名字(例如 safeCall("fppCamera:ResetPitch", ...) 里的那一串)
     不再当文案, 以前它会被翻成中文写回代码。
  3. 语言包里只有一个英文单词的条目(车漆颜色、身体部位名)不再套用官方字幕里
     同形的另一种译法(Body 被填成「尸体」、Black 被填成「布莱克」)。这类词改由
     模型按词面译; 已经写进模组的旧译文, 要点一次「↻ 重译」才会更新。

【v2.45.2 更新: 已完成的模组整块跳过; 修好「整份语言包补不进去」】
  1. 加载和机翻同时做: 复制并解析下一个模组, 和翻当前模组并行。实测 42 个有待译行
     的模组, 预处理 68.7 秒 + 翻译写回 96.0 秒, 串行要 164.7 秒, 实际 151.2 秒。
  2. 已经部署好、源文件也没动过、上一轮没有漏译的模组, 整块跳过: 只核一次清单里那些
     文件的 sha1, 不复制、不解析、不问模型。这条只在第 8 个勾选项「跑完覆盖回原模组」
     打开时生效, 面板上会显示「已是最新」。
  3. 修好「目标语言包是模板, 需要把缺的条目追加进去」的路径。以前追加的行数被算了
     两遍, 校验必然对不上, 整份文件被判「会破坏括号结构」而放弃写入 —— 一条也补不进去
     (Much Better Contracts 的 1,320 条就是这样丢的), 报错里两边的括号数还是一模一样的。
  4. 修好 WolvenKit 调用可能永久卡住: 命令行输出的管道被它启动的子进程占住时, 主进程
     退出后我们也读不到结尾, 会一直等下去(实测卡了半小时以上)。现在输出写临时文件,
     超时连子进程一起杀掉。

【v2.45.1 更新: 语言包不再拆掉 @if 守卫; 车的颜色/部位名也会翻】
  1. 「语言包 + 逻辑」写在同一份 .reds 里的模组(如 CyberwareEx), 头部用
     @if(ModuleExists(...)) 包着可选子模块的 import。以前抽语言包类时只留
     module / import 行, 守卫被丢掉 -> 缺装那个子模块的电脑上 redscript 编译
     失败, 整个脚本层的模组都不加载。现在紧贴 import 的 @if / @else 会一起带走,
     而修饰 public func 的注解不会被误搬。
  2. JSON 语言包里的单个单词(All / Paint / Body / Beige / Black ...)以前不算
     待译, 所以车库模组的部位名和颜色名整片是英文。判据与 .reds/.lua 的语言包
     统一后: Garage Manager 多 22 条、Vehicle Core 多 20 条。weapon / true / 12
     这类数据值仍然不收。
  3. 重跑时, 目标文件里已经有的译文不再重写(写回去是空操作), 也不再被当成
     「本轮新写回」塞回翻译记忆。DigitalVixenCore 少写 5071 行。
  4. 批量面板每一行右边多了「↻ 重译这个模组(丢弃本轮记忆)」: 解压还原后重跑
     之前点一下, 就不会再从翻译记忆里把上次那份译文搬回来。只删机翻与记忆来源,
     手改和官方语料不动, 同时删掉它在续跑记录里的那一行。

【v2.45.0 更新: 批量翻译快了, 因为慢的不是模型是 WolvenKit】
  1. 归档里只读源语言和目标语言。模组常带十几种语言的 json, 每读一个要 2.8 秒
     (WolvenKit 进程启动占大头), 而真正用得上的只有 en-us 和 zh-cn。
     实测 Nearby Auto Loot 加载 58.8 秒 -> 9.7 秒, Equipment-EX 40.3 -> 10.0 秒。
  2. 一个模组有几十个归档时(Much Better Contracts 有 72 个, 里面一个本地化都
     没有), 现在 4 路并行读目录, 并把结果缓存到 userdata\cache\archive_toc.json。
     实测 176.9 秒 -> 首次 53.9 秒 -> 缓存命中 7.8 秒。
  3. 模型侧的三个小修:
       * 模型预热一轮只做一次(以前每个模组都调一次);
       * 整批解析失败先整批重试一次, 再退化成逐条(逐条是 8 倍开销);
       * 批大小按文本长度自适应(短文本 8 条, 长文本 4 条)。
  4. 转换前会先检查文件在不在 —— 输入不存在时 WolvenKit 会直接崩溃且不报错。

【v2.44.3 更新: 同名条目写两遍会把后面的代码吃掉】
  1. 一份语言包里同一个条目名出现两次时(比如 DigitalVixenCore 的 155 行和
     220 行都有 FACC.UI.rowBodySlots), 以前两条同名行各生成一条同一位置的
     编辑, 第二遍按旧位置切文本, 会把后面的 `);` 和换行一起吃掉 ->
     REDscript 编译失败, 整个模组的脚本都不加载。
  2. 现在同名条目每一处都会写(以前第二处永远留在英文), 但只按位置算一次。
  3. 写盘前还会对一次括号结构(去掉字符串后数括号), 对不上就整批不写,
     报「写回会破坏括号结构」, 不会再把坏文件落盘。
  4. 已经坏掉的那一个文件已按原始下载包恢复, 并补上了少译的那一处。

【v2.44.2 更新: 批量面板可以折起「无需翻译」的目录】
  1. 面板加了「隐藏无需翻译」勾选框。255 个目录里只有 127 个有待译行,

  3. 勾选状态会记住, 不会因为重新扫描就被重置。

【v2.44.1 更新: 单个资源转换崩了不再拖垮整包】
  1. 组包时 WolvenKit 偶尔会自己崩掉(exit 3221225477 = 访问违例), 跟译文内容无关:
     同一份文件再跑一次就过。现在遇到会先自动重试一次。
  2. 重试还失败, 只跳过那一个资源, 其余照常打包; .xl 里也不会声明被跳过的资源
     (声明了会让 ArchiveXL 加载失败)。被跳过的资源对应的条数会从「写入」里扣掉,
     报告里写「N 个资源转换失败已跳过(对应 M 条未写入)」。
  3. 崩溃现场会留在 userdata\work\<mod>\build\<产物>\failed\ 下: 出错的 JSON 和
     WolvenKit 的完整输出。要复现或报错直接拿那个目录。
  4. 报错文字不再只截最后几行调用链, 会先把真正的异常行带上。

【v2.43.3 更新: 批量产物更干净, 译文不再丢占位符】
  1. 批量写回不再留 *.bak, 也不再建「撤销上次应用」记录。批量写的是输出根里的
     副本, 那份副本就是要部署的成品: 上一轮实测留了 633 个 .bak / 19.2 MB,
     撤销记录占 112 MB, 进游戏都没用。改错了重跑一次批量即可。
  2. 写回前过一道标记检查: 译文丢了 <Rich color="...">...</> 这种包裹标签、
     或者把 {value} 写成 %s 的, 位置明确的自动补回去; 补不回来的占位符
     这一条不写, 记一条「标记/占位符丢失」的失败, 宁可留英文。
  3. 一个 .reds 里放了好几套语言包(英语 + 法语 / 韩语)时, 只翻源语言那一段,
     别的语言原样不动。以前中文会同时写进法语段, 法语玩家的界面变成中文。
  4. 语言包和模组逻辑写在同一个 .reds 里的, Provider 只取语言包类里的条目。
     设置项文案不会再有「写进中文包」的错目标, 也就不会有对不上的失败。

【怎么启动】
  双击 "2077模组翻译器.exe"
  也可以把某个模组文件夹直接拖到 exe 图标上, 会自动加载。

【四步用法】
  1. 点「浏览...」选中模组文件夹
     (路径形如 E:\Vortex Mods\cyberpunk2077\某个模组)
  2. 点「加载/提取」
  3. 在「译文」列双击 → 输入中文 → 回车
     (回车后自动跳到下一行, 也可以用底部「上一行/下一行」)
  4. 全部填完后点「应用到模组」
     会先自动生成 .bak 备份, 再写回源文件。

【提取范围 (第二行的药丸开关)】
  [v] .lua 设置文本 (CET/Mod Settings)
      默认开启。关掉就只扫 .reds / .xml (旧版行为)。
  [v] 长句兜底 (可能含日志文本)
      默认开启。把「没有位置证据但像句子」的文本也收进来,
      类型标为「长句文本」, 里面可能混有日志/调试字符串,
      不需要的可以直接跳过, 或用筛选器把这一类隐藏。
  [ ] 调试文本
      默认关闭。开启后连内部状态字符串、日志调用参数一起收
      (类型同样标「长句文本」)。想看全量时才打开。
  [ ] 语言包文件 (en_US.lua / English.reds)
      默认关闭。这类文件是"某一种语言"的翻译表,
      开启后会一次性把十几国语言全列出来(行数暴涨),
      一般不建议整体翻译, 只在需要校对时单独开。

  注: v2.22 起语言包和设置文本会**同时**出现在一张表里
      (以前配到 Provider 语言包就只提取语言包, .lua 设置文本整片丢失)。

【类型说明】
  显示名称 / 描述 / 分类 / 模组名 / 选项文本
        = 模组设置菜单里的文字 (设置项)
  界面文本
        = 有明确证据的界面字符串: ui.addSwitch / ImGui.Button 的参数,
          this.Text 的 value, 赋值给 title/message 这类名字的字面量
  长句文本
        = 兜底收进来的句子与数据表名称, 可能是提示, 也可能是日志

【导出 / 协作】
  「导出 Excel」把当前表格存成 xlsx, 可以发给别人翻,
  翻好后「读入翻译表」自动按 文件+行号+原文 匹配填回译文列。

【筛选 / 搜索】
  顶部「筛选」可以只看 未填译文 / 已填译文 / 设置项 / 界面文本 / 长句文本;
  右边输入框可按 原文、文件名、上下文 搜索。
  结果超过 3000 条时表格只显示前 3000 条, 用筛选/搜索缩小范围即可
  (导出和写回仍然包含全部条目)。

【设置菜单】
  路径: 菜单栏「设置」→「本地模型 API 地址...」, 或右上角「设置」按钮。
    API 地址   例: http://127.0.0.1:11434/v1   (Ollama)
                   http://127.0.0.1:1234/v1    (LM Studio)
                   http://127.0.0.1:8000/v1    (vLLM / llama.cpp)
               不带 http:// 会自动补上, 末尾斜杠会自动去掉。
    模型名称   可留空, 留空时自动使用该服务的第一个模型。
    测试连接   会访问 <地址>/models, 返回可用模型列表, 用来确认地址对不对。
    保存       写入配置文件, 下次启动自动读取。
  「设置」菜单里还有「打开配置文件所在目录」, 方便直接看/改 json。
  注: 保存后即可用底部「翻译当前行 / 翻译全部未填」调用它做机翻。

【机翻用法】
  1. 先在「设置」里填好 API 地址 (可点「测试连接」确认)
  2. 选中某一行点「翻译当前行」→ 只翻这一条
     或直接点「翻译全部未填」→ 把所有空译文批量翻掉
  3. 批量过程中按钮会变成「停止机翻」, 点一下就停(已翻好的保留)
  4. 机翻结果只是草稿, 请逐条检查后再点「应用到模组」
  提示:
    * 发送给模型的是"原文"这一列; 已是中文的条目一般会原样返回
    * 需要显卡/CPU 跑得动, 7B 级别模型即可, 太小的模型术语会乱
    * 模型越慢, 批量越久; 单条超时 120 秒, 一批超时 180 秒

【重要提示】
  * Vortex 用户: 应用完必须在 Vortex 里重新 Deploy,
    改动才会同步到游戏目录。
  * 改完启动游戏时 REDscript 会重新编译,
    若报编译错误, 用同名 .bak 覆盖回去即可恢复。
  * 备份文件是 xxx.reds.bak / xxx.lua.bak, 与源文件同目录。
  * 应用后想回退, 点顶部的「撤销上次应用」; 它会恢复本次改动的文件,
    并删除本次新建的目标语言包和对应 .bak。
  * 会自动跳过: n"CName" / r"资源路径" / t"TweakDB" / 语言码 /
    纯标识符 / 文件路径 等非文本内容。
  * 配置文件在 %APPDATA%\2077ModTranslator\settings.json,
    删掉它就恢复默认设置(默认 http://127.0.0.1:11434/v1)。
  * 部分模组的界面文字放在 locales\*.json 语言包里,
    本工具会在状态栏提示「检测到 N 个语言包 json」但不提取
    (json 语言包处理为后续功能)。
