====================================================
  赛博朋克 2077  模组翻译器  v2.23
====================================================

【这是什么】
  把 2077 模组里的可翻译文本提取出来, 在表格里逐条填中文,
  再一键写回模组的图形工具。适合把英文模组汉化, 也适合修改已有汉化。

  v1.1 支持三类文本来源:
    * REDscript (.reds)   —— 设置菜单 @runtimeProperty 里的文本
    * 输入 XML (.xml)
    * CET Lua (.lua)      —— Mod Settings / Native Settings UI / ImGui
                             注册的设置名称、描述、分类、选项、按钮标签
                             这是 v1.1 新增的重点功能

【v2.42.3 更新: 批量进度换成本机 HTTP】
  1. v2.42.2 的改法还不够: 跑到第 54 个 mod 又崩了。查下来是「前端取事件」
     这一步照样要经过 pywebview 的桥 (每取一次就新开线程, 再回写界面),
     取 150 毫秒一次, 比原来推得还勤。
  2. 现在批量进度走一个只在本机回环 (127.0.0.1) 的只读端口, 由前端 fetch 取,
     全程不碰 WebView2。一次十分钟的批量, 桥调用从 1300 多次变成 0 次。
     端口是随机分配的, 只监听本机, 带一次性口令, 只读, 不占固定端口,
     也不会弹防火墙提示。
  3. 万一这个端口起不来 (被安全软件拦), 会自动退回旧方式, 面板不会卡死。
  4. 批量流程、续跑记录、崩溃日志都和 v2.42.2 一样, 没有改动。

【v2.42.2 更新: 批量崩溃与续跑】
  1. 修掉「批量跑到第 28 个 mod 时窗口整个消失」。原因是后台线程直接往界面
     推事件, 跨线程碰 WebView2, 跑多了会踩访问冲突。现在改成前端定时取事件。
  2. 续跑: 每跑完一个 mod 就记一笔。崩了、关掉了, 再点「开始」会跳过已完成的,
     界面显示「跳过上次已完成的 N 个」。改了模型 / 目标语言 / 复制选项就重新算。
     想整批重跑就点「清空输出」。
  3. 崩溃现场: userdata\logs\crash.log 与 batch.log。前者是崩溃时的调用栈,
     后者记着断在第几个 mod。真出问题时把这两个文件留着。

【v2.42 更新: 批量队列换成单模组流程】
  1. 旧的「扫描游戏目录已装 mod」队列删掉了。它只看得到 .archive 里的
     本地化表, 看不到 .reds / .lua / 语言包 json。全量实测:
       旧队列   74 个 mod / 2459 行
       新批量  101 个 mod / 16126 行
  2. 新批量 = 把单模组那套流程跑 N 遍:
       复制整个目录 → 三层提取 → 只翻未译行 → 写回副本
     原目录 (Vortex 缓存 / 游戏目录) 一个字节都不改。
  3. 复制规则
     · 贴图 / 音频 / 视频 / 字体默认跳过 —— 不参与翻译, 却占九成体积
     · .archive 默认跳过; 纯归档汉化的 mod 需要勾「包含归档层」(慢)
     · 产物固定在 userdata\batch\out\<mod名>\ , 重跑覆盖同名目录
  4. 每个 mod 一个独立会话, 表格那边不受影响; 记忆和术语表共用一份
  5. 预扫 286 个目录约 33 秒, 先列出「待翻 / 已有中文」再决定勾哪些;
     待翻 0 行的标「无需翻译」, 不复制也不翻译
  6. 已知问题 (属于后续单模组优化): lua 语言包的目标文件名固定生成
     zh_CN.lua, 而部分 mod 用的是 zh-cn.lua, 游戏按 zh-cn 加载,
     这些 mod 的 zh_CN.lua 不会被读到。ChineseSimplified.reds 不受影响。

【v2.41 更新: 按「位置」拦名字, 写回失败分两级】
  1. 三类「形态正常但位置是名字」的串不再进表
     · 位置标识符 call(sys,"Renew") 的方法名、cname("None")、
                  slotWorldPosition(c,"Head") 的插槽名、
                  以及 "a.read,b.read," 这种能力/协议清单
                  这一类的坏法最隐蔽: 文件照样编译、界面照样正常,
                  只是方法调不到、插槽查不到 —— 实测一个模组 304 行
                  译文里有 14 处是这种, 租约体系整个失效
     · 数据行     takemura|story_takemura|q112_done|20 这种竖线 id 表
                  翻掉任一段, 语音池查不到、fact 名失配
                  (Alive|Dead|Unknown、Yes|No 这种二选一照常翻)
     · 本地化键   getText("UI-Foo-label") 的实参; 译文在归档里
     全量 286 个模组对比: 候选 6517 → 6476(-0.6%), 只有两个已知损坏的
     模组变少, 其余 133 个一条都没动
  2. 写回失败分两级
     · 可疑(soft)   疑似代码碎片, 可能误报 —— 明细里有「仍要写入」
     · 必坏(hard)   骨架不一致 / 数据行段数变了 / 能力清单 —— 永不写
     骨架校验失败时只拒那一条, 同文件其余译文照常写回
     (以前一条坏行会让整个文件 0 条写入)
  3. 每条失败都能点「标记为代码」, 记进 userdata\user_skip.json,
     按 (相对路径, 原文 sha1) 记住, 以后加载直接不出现
  4. 机翻不再静默丢条: 模型返回空串或原样返回英文时逐条补翻一次,
     写回后状态栏报「候选 N · 写入 M · 跳过 K」
  5. 归档译文没变化时不重新打包; 拼接文本的首尾空格会保留
  6. getLabel=function() return "…" end 这类直接返回字面量的显示名也会进表
     (以前按钮的 label 译好了、getActionLabel 返回的英文却没人翻,
      因为那几行根本不在表里, 永远发现不了)

【v2.23 更新: 误报更少 + 界面更紧】
  1. 五类「像文本其实不能翻」的东西不再进表
     · 资源转储   kb_a:64:64:0|kb_b:32:32:1、common/masks (12)
     · 记录名     Items.tony_wet_t-shirt_red、Foo.Bridge::Hide;String
     · 技术串     ORDER BY name ASC、walk dist=%.1f busy=%.1f
     · 外文表     [en_us][pl_pl]... 、확인、LACK

  2. 一个文件里有多套语言时只收英文那一段
     · func XXX_EN_US / _RU_RU / _ZH_CN 这类分段, 只留 EN
     · class English / class Russian 两个语言包类并存时同理
  3. 工具条右侧会显示「已过滤噪音 N 条」, 扫描报告里按家族列出明细
  4. 界面收紧: 按钮 32→26px、表格行 34→27px、标题栏 40→34px,
     冷门按钮收进「更多 ▾」菜单(元素与快捷键不变)
  5. 实测 302 个模组: 26,337 行 → 23,679 行(-10%), 没有任何模组变多或清零

  v2.20 ~ v2.22 的功能(资源模式/字幕、批量队列、分层提取)见 README.md。

     · 关闭程序后仍可撤销; 每个模组保留最近 30 次写回记录

【怎么启动】
  双击 "2077模组翻译器.exe"
  也可以把某个模组文件夹直接拖到 exe 图标上, 会自动加载。

【四步用法】
  1. 点「浏览...」选中模组文件夹
     (路径形如 E:\Vortex Mods\cyberpunk2077\某个模组)
  2. 点「加载/提取」
  3. 在「译文」列双击 → 输入中文 → 回车
     (回车后自动跳到下一行, 也可以用底部「上一行/下一行」)
  4. 全部填完后点「应用到模组」
     会先自动生成 .bak 备份, 再写回源文件。

【提取范围 (第二行的药丸开关)】
  [v] .lua 设置文本 (CET/Mod Settings)
      默认开启。关掉就只扫 .reds / .xml (旧版行为)。
  [v] 长句兜底 (可能含日志文本)
      默认开启。把「没有位置证据但像句子」的文本也收进来,
      类型标为「长句文本」, 里面可能混有日志/调试字符串,
      不需要的可以直接跳过, 或用筛选器把这一类隐藏。
  [ ] 调试文本
      默认关闭。开启后连内部状态字符串、日志调用参数一起收
      (类型同样标「长句文本」)。想看全量时才打开。
  [ ] 语言包文件 (en_US.lua / English.reds)
      默认关闭。这类文件是"某一种语言"的翻译表,
      开启后会一次性把十几国语言全列出来(行数暴涨),
      一般不建议整体翻译, 只在需要校对时单独开。

  注: v2.22 起语言包和设置文本会**同时**出现在一张表里
      (以前配到 Provider 语言包就只提取语言包, .lua 设置文本整片丢失)。

【类型说明】
  显示名称 / 描述 / 分类 / 模组名 / 选项文本
        = 模组设置菜单里的文字 (设置项)
  界面文本
        = 有明确证据的界面字符串: ui.addSwitch / ImGui.Button 的参数,
          this.Text 的 value, 赋值给 title/message 这类名字的字面量
  长句文本
        = 兜底收进来的句子与数据表名称, 可能是提示, 也可能是日志

【导出 / 协作】
  「导出 Excel」把当前表格存成 xlsx, 可以发给别人翻,
  翻好后「读入翻译表」自动按 文件+行号+原文 匹配填回译文列。

【筛选 / 搜索】
  顶部「筛选」可以只看 未填译文 / 已填译文 / 设置项 / 界面文本 / 长句文本;
  右边输入框可按 原文、文件名、上下文 搜索。
  结果超过 3000 条时表格只显示前 3000 条, 用筛选/搜索缩小范围即可
  (导出和写回仍然包含全部条目)。

【设置菜单】
  路径: 菜单栏「设置」→「本地模型 API 地址...」, 或右上角「设置」按钮。
    API 地址   例: http://127.0.0.1:11434/v1   (Ollama)
                   http://127.0.0.1:1234/v1    (LM Studio)
                   http://127.0.0.1:8000/v1    (vLLM / llama.cpp)
               不带 http:// 会自动补上, 末尾斜杠会自动去掉。
    模型名称   可留空, 留空时自动使用该服务的第一个模型。
    测试连接   会访问 <地址>/models, 返回可用模型列表, 用来确认地址对不对。
    保存       写入配置文件, 下次启动自动读取。
  「设置」菜单里还有「打开配置文件所在目录」, 方便直接看/改 json。
  注: 保存后即可用底部「翻译当前行 / 翻译全部未填」调用它做机翻。

【机翻用法】
  1. 先在「设置」里填好 API 地址 (可点「测试连接」确认)
  2. 选中某一行点「翻译当前行」→ 只翻这一条
     或直接点「翻译全部未填」→ 把所有空译文批量翻掉
  3. 批量过程中按钮会变成「停止机翻」, 点一下就停(已翻好的保留)
  4. 机翻结果只是草稿, 请逐条检查后再点「应用到模组」
  提示:
    * 发送给模型的是"原文"这一列; 已是中文的条目一般会原样返回
    * 需要显卡/CPU 跑得动, 7B 级别模型即可, 太小的模型术语会乱
    * 模型越慢, 批量越久; 单条超时 120 秒, 一批超时 180 秒

【重要提示】
  * Vortex 用户: 应用完必须在 Vortex 里重新 Deploy,
    改动才会同步到游戏目录。
  * 改完启动游戏时 REDscript 会重新编译,
    若报编译错误, 用同名 .bak 覆盖回去即可恢复。
  * 备份文件是 xxx.reds.bak / xxx.lua.bak, 与源文件同目录。
  * 应用后想回退, 点顶部的「撤销上次应用」; 它会恢复本次改动的文件,
    并删除本次新建的目标语言包和对应 .bak。
  * 会自动跳过: n"CName" / r"资源路径" / t"TweakDB" / 语言码 /
    纯标识符 / 文件路径 等非文本内容。
  * 配置文件在 %APPDATA%\2077ModTranslator\settings.json,
    删掉它就恢复默认设置(默认 http://127.0.0.1:11434/v1)。
  * 部分模组的界面文字放在 locales\*.json 语言包里,
    本工具会在状态栏提示「检测到 N 个语言包 json」但不提取
    (json 语言包处理为后续功能)。
