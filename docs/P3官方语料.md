# P3 官方双语语料

> 官方语言包按主键对齐后，本身就是一份 16 万对的 en→zh 平行语料——
> 而且是**游戏官方自己的译法**，术语与语气天然一致。
> 实测 45 秒构建完成，库大小 43.1 MB。

> **P5 补记**：本文件最初的数字只覆盖基础游戏，漏掉了往日之影的整块语料。
> 现在 `extract_language()` 会合并 `archive/pc/content` 与 `archive/pc/ep1`
> 两个语言包，下面的数字已是最新。漏掉的经过见 `P5字幕覆盖.md`。

---

## 为什么能对齐

官方每种语言各一个文本包，资源结构完全一致，所以主键天然对应：

| 资源 | 对齐键 | 数量 |
|---|---|---|
| `onscreens` | `primaryKey` | 69,758 |
| `subtitles` | `stringId` | 94,599 |
| **合计** | | **164,357** |

基础游戏与往日之影各自的资源目录不同（`base/localization` 与
`ep1/localization`），两边都要读，否则狗镇那一整块字幕会静默缺失。

这个结论在 M0 就已经埋下伏笔：字幕的 `stringId` 是数字串，跨语言完全一致，
所以对齐靠主键而不是文本相似度，零歧义。

构建命令：

```powershell
python -m localization.official_tm build
python -m localization.official_tm stats
python -m localization.official_tm lookup "Inventory" "Street Cred"
python -m localization.official_tm terms "Equip the Legendary Sandevistan"
```

## 速度：为什么是 45 秒而不是半小时

两个关键点：

1. **`convert serialize` 支持传目录**，一次进程展开 7000+ 个字幕文件。
   逐个起进程（每次约 0.7 秒）会变成 70 分钟——差了三个数量级。
2. 解包结果缓存复用：第二次构建只重新展开，不再解包。

## 踩到的坑：官方语料并不干净

第一次建库后抽查发现：

```
Back  →  [en_us]Back
```

官方中文包里存在**漏翻的占位文本**，形如 `[en_us]xxx`，还有整段照抄英文的条目。
这些收进 TM 会直接污染译文。

`_is_usable_pair()` 的过滤规则（丢弃 5,780 条）：

- 目标文本以 `[xx-xx]` 开头 → 丢弃
- 目标里出现 `[en_us]` / `[en-us]` → 丢弃
- 目标语言是中文，但译文里**一个汉字都没有** → 丢弃

重建后审计：`dst 无汉字 = 0`，`src == dst = 0`，`Back → 返回`。

## 两个用法

### 1. 整句命中：加载时自动填充

`web_app._do_load_resource()` 在用户记忆之后跑一遍官方语料：

```
行数 66   官方命中 9   已填 9
```

**命中率约 10%**（实测 8 个 mod 共 219 条，命中 22 条）。原因是模组文案绝大多数
是原创内容，官方没有对应条目。所以它是「白捡的准确译文」，不能指望它替代机翻。

优先级：用户翻译记忆 → 官方语料 → 机翻。用户改过的永远优先。

### 2. 术语一致性：喂给机翻的提示词（更值钱的部分）

`TermHints` 从语料里挖出「英文术语 → 官方中文」，在每次机翻批次里挑出文本中
**实际出现过**的词，拼进 system prompt：

```
以下术语建议沿用游戏官方译法：arasaka industrial park=荒坂工业园；equip=装备
（若与上文自定义术语冲突，以自定义术语为准）
```

实测产出（2,720 条）：

| 英文 | 官方中文 |
|---|---|
| arasaka industrial park | 荒坂工业园 |
| trauma team international | 创伤小组国际 |
| sandevistan | 斯安威斯坦 |
| street cred | 街头声望 |
| quickhack | 快速破解 |
| dogtown | 狗镇 |

#### 术语是怎么筛出来的

直接取「短文本」会把 `failed` / `full` / `new` 这类普通词也收进来，喂给模型只会
添乱（`full=完整` 在 "Inventory is full" 里是错的）。四道过滤：

| 规则 | 挡掉的东西 |
|---|---|
| 单词必须首字母大写，多词短语直接收 | `failed`、`full` |
| 只从 `onscreen` 挖，不碰字幕 | `Body → 尸体`（字幕里的口语义） |
| 译文分歧度 ≤ 3 且出现 ≥ 3 次 | 高度依赖上下文的词 |
| 一个汉字对 ≥3 个字母 → 丢弃 | `more → 默` 这类切碎的碎片 |

还做了两件小事：被更长术语包含的短词会被去掉（有 `street cred` 就不要 `street`）；
用户术语表里已有的词不再重复（`Sandevistan` 不会说两遍）。

## 已知局限

1. **整句命中率只有 10%**，且集中在「覆写官方文本」类 mod。纯原创内容只能靠机翻。
2. **没有模糊句子匹配**。差一个标点就命中不了。要做的话需引入相似度检索，
   但中文译文插值容易出错，暂不实现。
3. **术语仍有少量歧义残留**（如 `body`），因为官方在 UI 里也用 "Body" 表示尸体。
   用户可通过自定义术语表覆盖。
4. 语料只支持 **en-us → zh-cn**。其他语言方向需要改 `build()` 的 `src_lang/dst_lang`，
   逻辑通用但没有实测。
