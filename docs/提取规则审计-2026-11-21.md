# 提取规则审计（2026-11-21）

目的：用一套**独立于提取器**的宽扫描，回答「本地模组库里到底还有多少界面文本没进词典」，
并定位每一类卡在哪一层。这里的数据后续可以直接拿来做基线对比。

## 一、方法

刻意不复用 `mod_text_engine` 的任何判据 —— 要测的是提取器漏了什么，扫描器必须比它宽。

1. **宽扫描**：遍历 `staging_dir` 下全部模组，对 `.reds / .lua / .yaml / .json / .xml / .txt`
   用正则抓所有字符串字面量（双引号、单引号，不跨行，处理转义），同时记录：
   - **外层调用名**：从字面量位置向左做**括号平衡**，找包住它的那一层 `(`，取调用名。
     （不能用「向左找最近的 `(`」，嵌套调用会抓错，会把 15,000 条误判成「无外层调用」。）
   - **前文 30 字符**：用来区分拼接操作数、赋值、数组元素、注释。
2. **基线**：读压缩包 `CP2077 Localization Pack.zip` 里 94 个 tsv 的全部 key。
3. **过滤**：只留「像自然语言」的候选（≥2 词 / Title Case 单词 / 全大写词），
   剔掉 snake_case、点分记录名、路径、URL、查表键、词内大小写跳变。
4. **分层回放**：对每个模组再跑一次 `extract_root_ex`，把候选逐层塞回
   `NOISE.hard_family` → `user_skip` → `collect`，看它卡在哪一步。

## 四、四类根因

### 4.1 `user_skip` 的「跳过」标记把整片文本埋了

`dist\userdata\user_skips.json` 里有 **18 个模组、838 条**「已跳过」标记。
ApexGrapple 一个模组 174 条，覆盖了它整个设置面板：

```
extract_root_ex 产出        243 条
  → user_skip 挡掉          162 条   ← 这里
  → collect 只剩             81 条
```

单文件跑（`Localization.reds` 放进临时目录）时 96 条英文全收，整个模组跑时只剩 4 条 ——
说明不是提取逻辑的问题。**2026-11-21 已清空**（备份 `user_skips.json.bak-20261121-140359`）。

### 4.2 模组显示名一律不翻

```
@runtimeProperty("ModSettings.mod", "Auto Drive Enhanced")
ModSettings.GetCategories(n"Auto Drive Enhanced")
```

以前 `rp_mod_starts` 把 `ModSettings.mod` 的页名整条放弃，理由是「注册处翻中文、
读取处 `n"X"` 还是英文，页签会裂成两个」。**那条理由只在写回源码时成立**；
现在的出口只有词典 + dll 渲染时替换，ID 一字不动，显示时才换字。

**2026-11-21 起 `rp_mod_starts` 已彻底删除**，`ident_texts` 守卫对 `@runtimeProperty`
的值位放行。实测 `Auto Drive Enhanced` / `Living Streets` / `Enemy Reinforcements` /
`Augur Collection` 全部进词典。

### 4.3 `this.Text(key, value)` 的值

`codeware_text_calls` 认这个形状，`_extract_reds` 第 2643 行也只收 value。实测：

- 值带首尾空格时（`" carry capacity"`、`"Busted. Fined "`）**能收到**，
  写盘时 `write_dicts` 还会补一条去空格的版本。
- 这些串大部分**已经有译文、只是没进词典**，属于「缺译文」而不是「提取漏」。
- 真正收不到的，是运行时拼出来的（见第五节）。

### 4.4 单字标签

```python
_UI_WORD_RE = re.compile(r"^[A-Z0-9][A-Z0-9'&/+:.\-]{1,27}$")   # General 匹配不上
```

只认全大写，首字母大写的单词（DVRCF 的 `b.Tab("General")`、`b.Section("Features")`、
`b.Slider("range", "Range")`）一个都进不来。Monowire Rework 因此只有 34 条、缺 6 个页签标题。
**2026-11-21 已放行 Title Case**，仍然要求 `_ui_label_position` 的位置证据。

## 五、不靠静态提取的部分（运行时补漏）

这些只能在游戏里跑出来，静态提取永远收不全：

- **拼接串**：`return "Unlocks the " + f("Monowire Lasso") + ".\n\nHold " + …`
  （Monowire 的两段专长描述、ApexGrapple 的 `"… from V and "` 之类）。
- **三元表达式**：`ImGui.Button(Duty.onDuty and 'Go off duty (10-7)' or 'Go on duty (10-8)')`。
- **模组自己封装的控件**：`controls.DynamicButton("All LUTs", …)`。

机制：`src/pack/cet_zh/init.lua` 把「流经 ImGui 但词典里没有」的串写进
`miss.tsv`，`ui_dict.build_all(..., runtime_miss=…)` 并入全局分片，
于是它们进得了「还差几条」、能被翻译，下一轮落盘生效。

## 九、换行归一化（同日补）

**问题**：redscript 里 `"a\nb"` 运行时是 `a` + 真换行 + `b`，而提取器保留的是
**源码原文**（反斜杠 + n 两个字符）。词典 key 按原文存、DLL 拿运行时文本做
逐字节比较，两边形态不同 —— **249 条带换行的长文本从来没生效过**，译文翻得
再准也不会显示。P7 合并出来的 39 条也带换行，同样是 0 收益。

**改法（三处一起归一化）**：

| 位置 | 改动 |
|---|---|
| `mod_text_engine.unescape_text()` | 把 `\n \t \" \\` 还原成真字符；5 个输出点（`_extract_lua`、`_extract_reds` ×3、`concat_literals`）+ `locale_pack` 都过一遍 |
| `ui_dict._clean()` | 真换行 → 空格（原有行为），于是词典 key 统一成「空格分隔单行」 |
| `ui_dict.load_memory()` | 给 memory 的 key 补一份同样归一化的变体 |
| `ui_dict._pick_text()` | 原文查不到时，按清理后的形态再查一次 —— 否则 240 多条会整片掉回待翻译 |
| `Main.cpp LookupText()` | 原样查不到、且串里确实有 CR/LF 才归一化重查；普通文本一次都不多扫 |
| `Main.cpp UnescapeInPlace()` | `ParseDict` 时把译文的 `\n` 还原成真换行，多行译文才不会原样显示 `"\n"` |

归一化规则两边一致：CR/LF/TAB → 空格、连续空白并成一个、**不 trim 首尾**
（两边都不 trim 才能逐字相同）。

**验证**：`BetterNetrunning.tsv` 里那条
`An enemy Netrunner is fortifying the network. Their progress bar fills…`
现在是空格形态且有译文；全量 `entries 24,525 / missing 879`，没有条目丢失。
DLL 重新编译后 sha256 `A37D7FB7…`，同步到 pack / 游戏目录 / exe 三处。

> 注意：源码里写成 `"\\n"` 的（双反斜杠）运行时就是**字面的反斜杠 + n**，
> 那 8 条保持原样是对的，不要当成 bug 抹掉。
