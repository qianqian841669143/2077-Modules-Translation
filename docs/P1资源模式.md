# P1 资源模式引擎

> 目标：把「官方/模组归档里的 CR2W 本地化资源」变成可翻译的表格行，
> 翻译完再打回成一个能被 ArchiveXL 加载的新 mod。
> **2026-10-30 端到端跑通，已在游戏内验证合并生效**（见文末证据）。

---

## 模块分工

```
src/localization/
    wkit.py        WolvenKit CLI 调用（独立进程，隔离 GPL）
    cr2w.py        CR2W 结构：三种 schema、entryId、文本读写、富文本标签
    xl.py          .xl 配置解析与生成（含 extend / 标量与列表两种写法）
    archive.py     定位游戏、解析目标 mod、解包
    builder.py     组包 → <name>.archive + <name>.archive.xl
    verifier.py    产物校验（离线）+ 读 ArchiveXL 日志（在线）
    pipeline.py    门面 Session：scan → set_text → build
```

与现有「源码模式」（`locale_pack.py` + `mod_text_engine.py`）完全并列，
互不依赖。源码模式处理明文 `.reds/.json/.lua`，资源模式处理归档里的 CR2W。

---

## 用法

```python
from localization import wkit, pipeline, verifier

cli = wkit.find_cli()                       # 自动探测，找不到返回 ""
s = pipeline.open_session(
        r"E:\...\archive\pc\mod\Foo.archive.xl",
        cli, workdir=r".l10n\work")

meta = s.scan()        # meta["total"], meta["languages"], meta["warnings"]
row  = s.rows[0]       # {"file","entryId","label","orig","trans","lang",...}
s.set_text(row["file"], row["entryId"], "译文")

result = s.build(name="Foo_zh-cn", outdir=r".l10n\out")
report = verifier.verify_build(result, s.last_spec, cli, s.workdir)
print(report.text())

builder.install(result, game_dir)          # 拷进 archive\pc\mod
```

## 三个关键设计决定

### 1. 只提交改动过的条目

ArchiveXL 的合并是**逐条目**的（`MergeTextEntry`：命中主键就覆写，否则追加），
不是整表替换。所以归档里不需要那份 9 MB 的 onscreens 全量副本，只要改过的几条。

实测：Quickhack_Fixes 有 11 条文案，改 3 条，产物资源 2086 字节、归档 8 KB。
若全量携带，单这一份就是十几 KB 起，官方 onscreens 则是 9 MB——批量处理时差三个数量级。

### 2. 资源路径必须放自己的命名空间

产物路径是 `l10n\<mod>\<lang>\onscreens\<n>_<原名>.json`，**绝不沿用原 mod 的路径**。

原因：归档里同名资源会在资源库中互相遮蔽。若我们写
`quickhack_fixes\localization\en-us.json`，就会顶掉原 mod 的英文资源；而我们只带了
改动条目，原 mod 其余文本会整段消失——这正是 CMT 那类做法的病灶。

### 3. `.xl` 用 `extend:` 挂接，不改原 mod

产物是**新增**一对文件，原 mod 的 `.archive` / `.archive.xl` 一个字节都不动
（实测原文件时间戳不变）。mod 更新时我们的译文不会被覆盖，也随时可单方面移除。

## 踩过的坑（都已在代码里处理）

| 坑 | 现象 | 处理 |
|---|---|---|
| 按路径猜本地化文件 | mod 命名毫无规律（`en-us.json` / `translation_strings.json` / `*_localization.json` / `02_s15_local.json`），一猜就漏 | 改成：归档里 `.json` 且是 CR2W 即候选，类型交给 `$type` 判断 |
| 沿用原资源路径 | 中文顶掉英文、原文整段消失 | 强制写进 `l10n\<mod>\<lang>\` |
| 字幕塞 Entries 文件 | `Resource "..." failed to load` | 必须给 `PersistenceSubtitleMap`（注册表）+ Entries 成对 |
| 路径写进 `subtitleFile.$value` | WolvenKit 报 `JSON value could not be converted to RedFileDto` | 写到 `DepotPath.$value` |
| 每次回写重建索引 | 6 万条目时 O(n²)，几十秒卡死 | `Session._index()` 缓存 `{entryId: entry}` |
| `pack` 输出名 | 打包目录叫 `stage` 就产出 `stage.archive` | 打包目录直接以目标名命名，省掉一次拷贝 |

## 已知缺口（P2 及以后）

1. **字幕能否覆盖原文未验证**。字幕走 `PushBack` 追加，我们的文本排在官方之后；
   若游戏按 `stringId` 建索引且先者优先，译文不会覆盖原文。P1 只保证「能加载、
   能被注册」，替换语义留到 P5 实测。
2. **尚未做语言筛选**（P2）。多语言 mod 会把全部语言扫出来，每行已带 `lang` 字段，
   `Session.rows_for(lang)` 已就绪，但「默认只显示 en-us、目标语言已存在则跳过」
   这条策略要等 UI 一起定。
3. **7 / 82 个 mod 无法自动找到归档**。归档名与 `.xl` 完全不同
   （`atomiic_vikki_hair_ccxl.xl` ↔ `Atomiic_Vikki_-_High Ponytail_CCXL.archive`），
   已加归一化模糊匹配，从 66/82 提升到 75/82；剩下 7 个需要用户直接选 `.archive`。
   P2 已给出明确提示文案。
4. **定向解包尚未实现**。目前一律全量解包；大 mod 会慢几秒。WolvenKit 的 `-w`
   是通配符不是正则，路径列表拼不出可靠选择器，留作后续优化。
