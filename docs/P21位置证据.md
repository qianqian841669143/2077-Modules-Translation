# P21 位置证据：按「这个字面量站在哪」拦标识符

v2.41.0 实现。同批完成的还有 P16（soft/hard 分级 + 单条覆盖 + 标记为代码）、
P18（竖线数据行）、P13（查表键）、P14（拼接空格）、P15（归档未变不重打包）、
P12/P17（空译文与 echo 重试）、P4/P6（前端状态）。

## 起因：Immersive Third Person 2.0.0 被翻了 14 处代码

`E:\Vortex Mods\cyberpunk2077\Immersive Third Person - Best Of Both Worlds V2 32203 2.0.0 …`
共 304 行中文，其中 **14 处翻在名字上**。当时的证据：

| 位置 | 原文 | 被翻成 | 后果 |
|---|---|---|---|
| `api.lua` L650/1670/1811/1940/1977 | `call(sys, "Renew")` | `"刷新"` | 租约续期失败 |
| `api.lua` L1682/1823/1952/1989 | `call(sys, "Release")` | `"释放"` | 租约释放失败 |
| `api.lua` L850/1473 | `call(sys, "Revision")` | `"修订版"` | 版本比对失效 |
| `api.lua` L1044 | `host.cname("None")` | `"无"` | 哨兵名占位失真 |
| `init.lua` L4551 | `slotWorldPosition(c, "Head")` | `"头部"` | 头部位置查询静默返回 nil |
| `tpp_camera_api.reds` L850 | `CapabilityRoster()` 的点分逗号清单 | 半中半英 | 外部能力发现解析不出任何一项 |

`Renew`/`Release` 是 `host.call(obj, name, ...)` 的方法名；方法不存在时
`host.call` 返回 `ok=false`，功能走失败分支，**文件照样能编译、界面照样正常**。
这是「静默失效」里最难查的一类，比语法崩掉更糟（崩了至少能看见）。

当时这 14 处**一条都过不了现有守卫**：`looks_like_code_fragment` 看的是括号/引号
形状，`Renew` 形状完美；P18 的 `|` 形状规则也不命中。它们的共同点是**位置**。

## 判据（一）：位置的三种来源

`mod_text_engine.name_position_starts(toks, spans, by_start)`，只认**直接实参**
的那一个字面量（中间夹了变量就不管：宁可漏判，也不误伤）。

1. **`_NAME_ARG_CALLS`**：被调函数的指定参数位是名字。
   - `call(obj, "Method")` → 第 1 个参数（CET 远程调用的方法名）
   - `cname` / `StringToName` / `ToStringCName` / `StringToEnum` → 第 0 个
   - `GetSlotTransform` / `GetSlotWorldTransform` / `GetBoneWorldPosition` /
     `FindBone` / `AttachSlot` → 第 0 个
   - `Equals` / `StrSplit` → 第 1 个
2. **`_NAME_CALLEE_HINT_RE`**：被调名里带 `slot|bone|transform|attach|factor…`
   (`fact`、`tweakdb`、`recordname`、`persist`、`entityid`) → 该调用的字符串参数
   一律当名字。靠它接住「名字经由本地包装函数中转」的情况：
   `slotWorldPosition(slotComp, "Head")` 光看参数位判不出来，但函数名在说。
3. **`_is_name_literal`**：无空格、纯 ASCII 的单词或点分名；**中文直接放行**
   （已经是中文说明坏在别处，或者就是历史译文——那里再拦，用户连改都改不了）。

## 判据（二）：形状 —— 点分逗号清单

`NOISE.is_protocol_list`：无空格、同时含 `,` 和 `.`、每段都是点分标识符。
挡的是 `CapabilityRoster()` 那种 `"meta.read,perspective.read,events.push,"`。

## 判据（三）：竖线数据行（原 P18）

`NOISE.is_data_row`：段数 ≥3、每段都是 `[A-Za-z0-9_.:-]`、无空格、至少一段像 id
（snake_case 或纯数字）。`takemura|story_takemura|q112_done|20` 命中；
`Alive|Dead|Unknown`、`Yes|No` 不命中——真正的二选一界面文本照样翻。

写回侧还有一条硬线（`guard_level`）：原文是数据行时，译文的**段数与每段属性**
（ASCII 名 / 中文）必须一致，否则拒写。这种坏法在文件层面完全看不出来
（照样编译、照样能读，只是语音池查不到、fact 名失配）。

## 实测：全量 286 个模组 A/B

把新判据临时关掉再扫一遍（`p21_ab.py`）：

- 135 个模组有候选，合计 **6517 → 6476 条（-41，-0.6%）**
- 只有两个模组的候选数变了，且都是已知的损坏案例：
  - Immersive Third Person **-19**
  - GHXST Companion **-22**（正是 P18 记的那批竖线数据行）
- 其余 133 个模组**一条都没少**

ITP 文件级核对（还原成英文后的版本）：`api.lua` 65 处、`init.lua` 26 处、
`tpp_camera_bridge.reds` 16 处、`tpp_camera_notify.reds` 21 处被识别为名字位置，
逐条打印后**全部是真名字**（`call` 方法名、`makeTweakDBID("AttachmentSlots.TppHead")`、
`Equals(situation, "combat")`、`mod.cname("xtpp_takeover")` …），没有一条是 UI 文案。

## 顺带修掉的两个「同一类」问题

- **P13 查表键**：`getText("UI-Foo-label")` / `getTextOrKey(...)` 的实参是 key。
  Lua 路径以前没有这道判据，`repeatable_ncpd_gigs` 的 4 条候选全是
  `"reward.numOfDraws-label"` 这类 key——翻掉就是查表断供，而界面回退显示的
  正是那句中文。补上 `LOC_CALLS` 后该模组源码层从 4 条降到 0 条（真文案在归档里）。
- **P14 拼接空格**：`label="Restrict "..gig:GetQuestName()` 写回成
  `label="限制"..` 后，面板显示「限制Japantown…」。现在字面量紧邻 `..` 时保留
  原文首尾空白（只在拼接上下文里做，普通字段不多加空格）。

## P11 的结论：只做「getter 直接返回字面量」

`settings.category(name, …)` 的 arg0 是键、`settings.tab(name, label, …)` 的 arg1
是显示名。实测 240 个键位字面量里 **0 个**被当候选（键都是 camelCase 单词，
`is_translatable` 的「≥2 个英文词」本来就不收），所以键守卫今天收益为零，
`CALL_RULES` 补 `tab`/`subcategory`、支持赋值式包装函数声明这两条也都不做。

真正漏掉的是 `getLabel=function() return "…" end` 这种**直接返回字面量**的显示名：
前面不是 `label =`（中间隔了 `function`），也没有调用包装；长句兜底又要求首字母
大写，而 `"[For Dev] Restricted Gig Settings"` 首字符是 `[`，于是永远进不了表 ——
用户翻完整个模组，面板上那几个按钮还是英文。

加了一条 `_GETTER_RE`（`getLabel` / `getActionLabel` / `getName` / `getTitle` /
`getDescription` / `getDesc` / `getTooltip` + `= function(...) return "…"`）。
全量 286 个模组命中 **12 处，全是显示名**（6 对「英文原版 + 已汉化副本」），
零误伤。收获不只是那个 `[For Dev]` 面板项：

| 模组 | 漏掉的按钮名 |
|---|---|
| `repeatable_ncpd_gigs` | `Show ID` / `Restore Prefab` / `Terminate Gig` / `Reset Gig` / `Reset Counts` |

这 5 个按钮的 `label=` 都已经译成中文了，只有 `getActionLabel` 返回的英文没人翻 ——
之前它们根本不在表里，所以永远发现不了。
