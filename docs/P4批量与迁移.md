# P4 批量队列与版本迁移

> 一次把游戏里几十个 mod 排队跑完；mod 更新后只重译真正变了的条目。
> 单个 mod 失败不影响其他，随时可取消，且**永远不自动装进游戏**。

---

## 为什么需要

P1–P3 做通了「单个 mod」的完整链路，但实际使用形态不是这样：装了一百来个 mod，
有本地化资源的有几十个。逐个打开、填译、组包，一个下午就没了。

第二个问题是 mod 会更新。更新后重新翻译一遍全量文案既慢又浪费——其中
绝大多数条目一个字都没变。

所以 P4 只解决两件事：**排队**和**增量**。

---

## 队列怎么跑

```
探测（哪些 mod 有本地化资源）
  → 勾选
  → 逐个：扫描归档 → 填译（记忆/官方语料/上次快照）→ 机翻剩余 → 组包 → 校验
  → 产物只写输出目录
```

界面上是一个列表：mod 名、条目数、类型、状态。状态从「待翻译」走到
「完成」「部分失败」「无条目」，下面一行给出迁移明细与耗时。

几个刻意的边界：

- **不自动安装**。产物落在 `%APPDATA%\2077ModTranslator\output\`，
  装不装由用户点。批量装几十个包进游戏目录，出问题很难收拾。
- **跳过自己的产物**。名字以 `_zh-cn` 结尾的 `.xl` 直接排除，
  否则第二次批量会把上次译好的成品当成新 mod 再翻一遍。
- **失败隔离**。某个 mod 解析失败或机翻报错，只把这一条标红，队列继续。
- **可取消**。取消在两个 mod 之间、以及每 8 条机翻之间检查，不会卡死在一个长任务里。

---

## 探测成本与缓存

探测不能直接 `Session.scan()`——那会解整包，贴图和音频的搬运时间占九成以上。
`batch.probe()` 只用 `-w *.json` 解出 JSON，再判断里面有没有本地化资源。

实测（159 个 `.xl` 的游戏目录）：

| mod | 归档大小 | 探测耗时 | 条目 |
|---|---|---|---|
| citizen_breast_physics | 0.0 MB | 2.0s | 0 |
| Quickhack_Fixes | 0.0 MB | 4.7s | 11 |
| Pump_Shotgun_Pack | 411.6 MB | 4.9s | 74 |
| immersive_third_person | 896.9 MB | 2.1s | 0 |

**平均 3.1 秒/个**，且和归档体积基本无关——因为通配符过滤在解包阶段就把非 JSON
挡掉了。首次全量扫描约 **8 分钟**。

结果按 `(归档路径, mtime, size)` 缓存到 `batch/index.json`，之后打开面板秒出；
mod 一更新（mtime/size 变了）自动失效重探。「重新探测」按钮强制全部重扫。

---

## 版本迁移：按 entryId，不按文本

mod 更新后，用户之前调过的译文不能丢，也不能全部重翻。

这里有一个容易做错的选择：**按原文文本比对**。问题是原文改一个标点就是新句子，
按文本比对会把它当新条目重翻，而 `entryId` 是稳定的主键，能准确区分
「换了文本」和「换了排版」。

每次成功组包后，把 `entryId → [原文, 译文]` 快照写进 `batch/state.json`。
下次跑同一个 mod：

| 情况 | 处理 |
|---|---|
| id 在、原文相同 | **直接复用旧译文**，不调模型 |
| id 在、原文变了 | 视为改动，重新翻译 |
| id 不在（新条目） | 新增，翻译 |
| 旧 id 在新版本里消失 | 计数为「删除」，出包时自然不带 |

复用的优先级排在用户记忆之后、机翻之前，所以用户改过的译文永远赢。

### 实测

拿 `Quickhack_Fixes`（11 条）连着跑两次：

| | 新增 | 改动 | 相同 | 复用 | 实际机翻 |
|---|---|---|---|---|---|
| 第一次 | 11 | 0 | 0 | 0 | **11 条** |
| 第二次 | 0 | 0 | 11 | 11 | **0 条** |

第二次一条都没调模型，产物依然完整——这就是增量重译。

## 顺手修掉的一个真问题：富文本标签没人校验

跑真实模型时抽查译文，发现有的行里 `<Rich color="...">` 标签被模型吞掉或改坏。

`cr2w.py` 里其实早就写了 `rich_tags()` 和 `tags_match()`，但**全仓库没有任何地方调用**
——等于没校验。源文件模式下用户会逐条看，批量模式是无人值守的，坏标签会直接进游戏，
表现为 tooltip 里冒出源码，或者整段格式失效。

处理方式是「安全失败」：

- 每条机翻译文与原文做标签比对
- 对不上就**丢弃这条译文**，让该条目保留原文（英文）
- 计数并在队列行显示「标签不符 N（留原文）」

比对用宽松版 `tags_ok()`：只比标签的种类与出现次数，**不锁顺序**。理由是
中文语序和英文不同，整块 `<Rich>…</Rich>` 跟着从句搬家是合理的；
真正的风险是吞标签、截断、改名，这些都会被数量比对挡住。

实测 11 条里有 1 条被吞标签 → 留原文，机翻 9 条 + 官方语料 1 条。

> 宁可让一个 tooltip 显示英文，也不要让它显示坏掉的标记。

## 已知限制

1. **队列不含安装**。装几十个包进游戏目录风险太大，留成手动。
2. **快照只增不减**。`state.json` 会随 mod 数量线性增长（每个 mod 几 KB 到几百 KB），
   目前没有清理入口，只能手删。
3. **不检测跨 mod 术语冲突**。两个 mod 对同一个词用了不同译名时不会提示，
   靠用户术语表兜。
4. **机翻串行**。为了不打爆本地模型，批次是按 mod 顺序、每批 8 条串行的；
   几十个 mod 同时翻译会很慢，这是刻意的取舍。
5. 批量面板只处理资源模式（`.archive` 内的 CR2W）；源文件模式的批量仍是逐个加载。
