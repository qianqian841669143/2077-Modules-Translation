## 1. 这是什么

把《赛博朋克 2077》模组里的可翻译文本抽成表格，翻好之后按行写回模组源文件（或打包成
一个新的翻译 mod）的本地桌面工具。重点不是「一键全自动」，而是：

- **抽得准**：只收真正给玩家看的文本，代码里的标识符、查表键、事件名、数据表一律不碰；
- **写得回**：逐行按原文匹配写回，改坏了能撤销；批量改动有部署清单与预演；
- **不重复翻**：同一句只问一次模型（翻译记忆），官方已有的译法优先套用。

技术栈：Python 3.14 + pywebview（WebView2）+ 原生 HTML/JS + SQLite/JSON 记忆库，
打包为单文件 exe。

## 2. 支持哪些文本

| 层 | 文件 | 抽取依据 | 写回方式 |
|---|---|---|---|
| 语言包 | `*.reds`（Codeware `ModLocalizationPackage`）、`en-us.json`、`en_US.lua` 等 | 语言包类的条目、JSON 叶子键、Lua 的 `Key = "..."` | 按条目名/键写目标语言文件；`.reds` 会自动保留 `@if` 守卫、生成 Provider |
| 源码 | `.lua`（CET / 原生设置 UI / ImGui）、`.reds`、`.xml` | 已知 UI 调用、`label =` / `@runtimeProperty`、`getLabel` 返回字面量、成对文本表、模组自己的动作注册器（含 `local A = Settings.RegisterAction` 这类别名）、菜单标题 `return "…", opts`、长句兜底 | 原地替换字符串字面量，带括号/占位符/转义形态校验 |
| tweakdb | `r6/tweaks/**/*.yaml`（含 `.yml`） | `localizedDescription` / `localizedName` / `localizedTitle` 的**内联**文案（`localizedDescription: 'Uploads a priming daemon …'`），类型按字段名给，上下文写记录名 | 原地替换 YAML 单/双引号标量：`'` 写成 `''`、真换行写成 `\n`，明文，不需要 WolvenKit |
| 归档 | `.archive` 里的 `localization` 资源 | 需要游戏目录与 WolkenKit CLI，解析归档内的本地化条目 | 组成新的 `_zh-cn.archive` / `.xl`，可一键装进游戏 |

**不抽的东西**（都踩过坑，写在代码注释里）：方法名与插槽名、`StringToName` 之类的记录名、
`getText` 查表键、竖线分隔的数据行、`0x…` 十六进制、色值、`player_crouch_enter` 这类
名字形状的字符串、**代号**（2-4 个字母的全大写串：`shortName = "CET"` / 页签标题
`ENC` / `MCM`——模组列表每行前面那个小标签、设置面板的页签，翻了会变成
「中央情报局」「神经连接」；判据是**值**不是字段名，所以 `shortName = "Auto Drive"`
这种真文案照收）、**查表键**（带空格的 `Gameplay-Items-Item Type-Prt_Fragment`、
两段式的 `GR-UiHomes`——`this.T(…)` / `text(键, 兜底)` 这类自造查表函数的实参，
翻了界面显示原始键；只拦没有位置证据的字面量，`this.Text("键", "值")` 的值照收；
tweakdb yaml 里 `displayName: murphys_web_name` / `localizedDescription: murphys_web_desc`
存的也是键，只有**内联引号文案**才进表），
以及**无空格却带 `:` `()` 的调用链**
（`fppCamera:ResetPitch`）。

## 3. 单模组流程

1. **选择模组目录**（或直接拖 `.zip` / `.archive.xl` / `.archive` 进来）→「加载 / 提取」。
2. 表格里逐行填/改译文。列：序号、跳过、文件、行号、类型、上下文、原文、译文。
   - 类型：显示名称 / 描述 / 分类 / 模组名 / 选项文本 / 界面文本 / 长句文本 / 语言包；
   - 左侧色条是**译文来源**：手改（最高）> 官方 > 官方待核 > 记忆 > 机翻；
   - 过滤器：全部 / 未填 / 已填 / 原文=译文 / 官方 / 官方待核 / 记忆 / 各类型 / 已跳过。
   - **跳过会被记住**：勾上就落到 `userdata\user_skips.json`，下次加载同一行默认还是
     勾上的（提示「N 条按上次的「跳过」自动勾选」），取消即删。它是「暂时不想翻」，
     行还在表里；要「以后彻底不出现」用应用失败明细里的「标记为代码」（那份是隐藏，
     存在 `userdata\user_skip.json`）。两份记录按（模组目录名 + 相对路径 + 原文）记，
     归档层的行没有磁盘路径，不参与。
3. **机翻**：整表、选中行、当前筛选结果都能翻；「重新翻译」不查记忆，强制问模型。
4. **应用到模组**：按行写回。写回前会核对同一批文件里还有多少行没译，写回后报告
   「候选 / 写入 / 跳过」。
   - 源码层自动留 `.bak`（可用「还原」撤销）；
   - 被判定为「疑似代码片段」的行只允许**单条**强制写入，批量永远不给这条路。
   - **占位符顺序**：`string.format` 按位置取参数，译文把 `%s` / `%d` 的顺序换了，
     个数还是一个不少，运行时就会 `bad argument #3 to 'format' (number expected,
     got string)`（MCM `modules\core.lua:1344` 那次整块面板报错就是这么来的）。
     写回前比对两边的占位符序列，顺序不一致的不写回，记软失败
     「占位符顺序变了, string.format 按位置取参数会崩」——默认拒绝，确有必要可以
     单条覆盖。中文语序想调只能改句子，不能让占位符换位。
    - **查表键永远不写**：`this.Text("键", "译文")` 的第一个参数是语言包的键
      （`LocKey#` 拿它查文本），按行号兜底也不会挑中它；一行只剩键时按失败报出来。
    - **`<Rich …>` 标记**：开头/结尾的标签丢了补回来，关闭标记只补到配平为止
      （译文多带的 `</>` 会删掉），句中标签或 `{占位符}` 丢了按软失败拦下。
    - **模型跑飞**：译文里同一段连写 3 遍以上（而原文不这么重复）、或者占位符比原文
      多出一大截，按软失败拦下；翻译记忆里同样的坏条目在取用时会自动丢掉。
5. **撤销上次应用**：一次应用（含混合层）只留一条撤销记录，恢复全部改动过的文件。

## 4. 批量翻译

流程：扫描安装缓存目录 → 勾选要跑的模组 → 每个模组「复制到输出目录 → 提取 → 机翻 →
写回副本」，可选**跑完覆盖回原模组**。

- **扫描**：预扫 `staging_dir` 下的一级目录，显示每个模组可提取的行数；读取失败的单独列出来。
- **续跑**：参数指纹（目录、语言、模型、部署开关等）相同且已跑完的模组自动跳过；
  面板上的「↻ 重译」会作废该模组的续跑记录并清掉它的记忆条目。
- **预演（只预演不写）**：算出会覆盖/新增哪些文件，只写
  `userdata\batch\deploy-<时间>.csv`，不动原模组目录。
- **覆盖回原模组**：按文件覆盖回安装缓存目录里的那个模组（副本里没有的文件保持原样），
  每个模组留一条撤销记录。
- **已是最新（S6）**：上一轮部署过、源文件 sha1 未变、提取引擎指纹一致、且没有漏译/失败的
  模组整块跳过，只核一次部署清单，不复制不解析不问模型。指纹是「提取规则版本号 + 程序版本号」
  （v2.52.0 起），所以**每次升级都会让这些记录失效一轮**，新规则能抽到的行才会重跑；
  文件内容没变就不会重写。
- **归档产物复用**（v2.52.0）：资源层组包前先比三条 —— 源归档 sha1 未变、这次要写进归档的
  译文对（`资源路径|entryId|译文`）与上次一致、上次产出的 `<mod>_zh-cn.archive` 与 `.xl`
  还在且 sha1 对得上。三条全中就不调 WolvenKit，直接用现成产物；任一条不同就重打包。
  一批 45 个模组里归档层原本占 87% 的时间，命中复用后这部分几乎为零。记录在
  `userdata\cache\archive_reuse.json`，清理缓存即可强制重打。
- **产物卫生**：副本里不留 `.bak`、不留撤销记录；`.mb-out-root` 标记用来确认目录是我们建的。
- **并行**：加载下一个模组（复制 + 解析）与当前模组的机翻并行，事件流仍是单线程按序发出。
- **导出结果**：把本轮跑完的模组导成 CSV（一行一个，UTF-8 BOM，Excel 双击就开）。列有
  状态、总行、待译、已有中文、记忆命中、机翻、写入、失败、未译、复制文件、耗时、
  部署（已部署 / 预演 / 失败）、覆盖 / 新增与备注（整块跳过的原因、部署说明、写回
  失败的首条原因、未译样例）。取消掉的模组不算跑完、不导出。跑完会落一份在
  `userdata\batch\last-run.json`：重开程序后导的就是上一轮那一份（提示「上次跑完的」），
  跑新的一轮会覆盖它，「清空输出」把它一起删掉。

## 5. 翻译记忆与官方语料

- **翻译记忆**（`userdata\memory.json`）：同一句只问一次模型；命中直接填。
- **官方双语语料**（`userdata\official_tm.sqlite`）：把官方语言包按主键对齐，得到游戏自己的
  en→zh 译文。加载模组时按「手改 > 官方 > 记忆 > 机翻」的顺序预填。
  - 多词短语且官方只有一种译法 = 稳；单词条 = 待核（`official-weak`）。
  - **语言包里的单个英文词不采用官方弱匹配**：`Body → 尸体`、`Black → 布莱克` 是字幕里
    同形的另一个义项，这类词留给模型按词面译。
- **术语表**（`userdata\glossary.json`）：官方语料里挖出的术语，拼进提示词，保证译名一致。
- **重译**：清空某行译文后重翻会先删掉这一句的机翻记忆，否则记忆会把旧译文原样填回来。

## 6. 归档模式

用于 `.archive` 里的本地化资源，需要**游戏目录**与 **WolvenKit.CLI.exe**。

1. 设置里填好两个路径 →「检测资源模式环境」（CLI 版本、游戏是否定位）。
2. 打开 mod 的 `.archive`（`ArchiveXL` 的 `.xl` 会自动找配套 `.archive`）。
3. 表格里翻译归档条目（资源行没有行号，用条目 ID 定位）。
4. 「应用」= 组包：产物写进 mod 目录里归档旁边，原归档不动；可「安装到游戏」
   （只写 `archive\pc\mod` 下两个文件）。
5. 撤销/还原对归档层同样有效，与源码层共用一条事务。
6. 归档里**只要有 `.json` 就会解包**（判断的标准是解包后的 CR2W 头，不是目录名）：
   本地化表的命名毫无规律（`localization\en-us.json`、`translations\translation_strings.json`、
   `02_s15_local.json` 都见过），按目录名预筛会把整包文案挡在门外——Immersive
   Cyberware 的 43 条物品名/描述就是这么丢的（`Holo Display: Ads`）。纯资源归档
   没有 json，照样不会被解包。

## 7. 界面语言（多语言机制）

- 文案即键：源码里 `_tr("中文原文")` / 前端 `T("中文原文")` / `data-i18n="中文原文"`，
  查表键就是这句中文原文。
- 内置语言目录：`src/locales/*.json`
  ```json
  {
    "code": "en-US",
    "name": "English",
    "strings": { "失败": "Failed", "覆盖 %d": "%d overwritten" }
  }
  ```
- 没有译文时**原样退回中文**，不会报错；缺哪句补哪句即可。
- 追加语言不用改代码：把同格式 json 放进 `userdata\locales\`，重启后出现在
  「设置 → 界面语言」里。
- 自测会校验：界面用到的每个中文 key 在 `en-US.json` 里都有译文，且 `%s` / `%d`
  占位符数量一致。

## 8. Vortex 用户须知

- 工具改写的是**安装缓存目录**（`staging_dir`，例如 `E:\Vortex Mods\cyberpunk2077`），
  Vortex 用硬链接把它和游戏目录连起来——所以写入后需要在 Vortex 里 **Deploy** 一次，
  游戏才读得到；界面状态栏与写回完成提示都会提醒。
- 下载包目录只读，用来判断装的是哪个版本。
- 加载时会提示该目录是否**生效**（Vortex 没部署的话，改动进不了游戏）。

## 9. 设置项

| 分组 | 设置 | 说明 |
|---|---|---|
| 模型 | API 地址 / 模型名 | 任意 OpenAI 兼容接口；留空模型名取 `/models` 第一个 |
| 翻译 | 目标语言 | 简体中文 / 繁體中文 / English / 日本語 / 한국어 / Русский / Español / Deutsch / Français |
| 翻译 | 使用翻译记忆 | 加载时自动预填 |
| 翻译 | 深色模式 | 主题 |
| 资源模式 | 游戏目录、WolvenKit.CLI、归档原语言、跳过已是目标语言的文本 | 归档层用 |
| 批量 | 批量输出目录 | 产物根目录，留空则不进行批量翻译 |
| Vortex | 安装缓存 / 下载包 / 自动探测 / 扫描活动映射 | 目录与「这个目录是否生效」的映射表 |
| Vortex | 加载时提示该目录是否生效 | 关掉可少一次检查 |
| 官方语料 | 使用官方语料 / 单词条也套用 / 构建官方语料 | 约 13 万对，1 分钟内构建完成 |
| 模型 | 启用本地模型 / 立即释放显存 | 停用即卸显存（Ollama `keep_alive=0`） |
| 模型 | 关闭时询问是否停止本地模型 | 默认开；关掉后关窗直接退出，模型继续常驻 |
| 界面 | 界面语言 | 内置中文/英文，可自行追加 |
| 缓存 | 刷新大小 / 清理选中 | 见下 |

**缓存清理**（设置页底部）会列出各类缓存占了多大，勾选后一次清掉：

| 项 | 目录 | 说明 |
|---|---|---|
| 提取缓存 | `cache\` | 归档目录的扫描结果，重建很快 |
| 中间文件 | `work\` | WolvenKit 解包/组包的中间产物 |
| 批量输出副本 | `batch\out\` | 下次批量会重新生成；续跑记录 `run.jsonl` 与上一轮导出报告 `last-run.json` 一起删（续跑记录留着下一轮会把已完成的模组整块跳过） |
| 撤销记录 | `undo\` | **删了就不能再「撤销上次应用」** |
| 官方语料导出 | `corpus\` | 重建官方语料时重新生成，需要游戏目录 |
| 日志与报告 | `logs\`、`reports\` | 排错用，删掉不影响功能 |

只删这些目录**里面**的东西，目录本身与批量输出目录的 `.mb-out-root` 印章都留着
（印章没了 `batch_clear` 就不肯认领那个目录）。`memory.json`（翻译记忆）、
`official_tm.sqlite`（官方语料）、`settings.json`、`glossary.json`、`locales\`
一律不碰——它们各有各的入口。批量或机翻正在跑时接口会拒绝清理。

## 11. 自测与排查

```powershell
python tools/selftest.py        # 全套自测：提取/回填/归档/批量/记忆/部署/多语言
python tools/scan_lua_format.py # 体检：扫游戏里已部署的 .lua，找必崩的 string.format
```

遇到问题先看：

1. `userdata\logs\batch.log`（卡在哪个模组、哪个阶段）、`crash.log`（Python 层的崩溃栈）；
2. 面板状态栏的提示（例如批量事件通道多久没响应）；
3. `userdata\reports\` 里的扫描/校验报告。

常见现象：

| 现象 | 处理 |
|---|---|
| 写回后游戏里没变 | Vortex 里 Deploy 一次；确认改写的是安装缓存目录 |
| 游戏里某块设置面板一操作就报 `bad argument #3 to 'format'` | 那一行的占位符顺序被换过（`%d` 拿到了字符串），跑 `tools/scan_lua_format.py` 定位文件与行号 |
| 某行「写回会破坏括号结构」 | 该行译文里括号/引号与原文形态不一致，按提示改 |
| 批量卡住不动 | 看 `batch.log` 最后一个 mod 和最后一行 `stage`；关掉重开，已完成的会自动跳过 |
| 批量跑到一半整窗消失 | 先看 `batch.log` 最后一行 `stage`（复制/加载/机翻/写回/部署）定位到阶段；重开程序点「开始」会从断点续跑（`run.jsonl` 里的模组自动跳过）。这类崩溃是 C 层 abort（系统事件日志里 `ucrtbase.dll` / `0xc0000409`），Python 拿不到栈 |
| 译文没生效、仍是旧的 | 「↻ 重译」会作废续跑记录并删掉这部分机翻记忆 |
| 应用时报「语言包类抽取自检未通过（类数/this.Text 条数/括号对不上）」 | v2.51.6 之前，一个 `.reds` 里同时有两套语言包（英文 + 西班牙语）时会拿**整个文件**的 `this.Text` 条数去比**抽出来那个类**的条数，永远对不上、整层被拒（Gang Retaliation 的 298 行）。现已改成按抽出来的类比对；升级后重新应用即可，`ChineseSimplified.reds` 与 Provider 分支会自动生成 |
| 语言包里 `this.Text("键", "译文")` 的第一个参数变成了中文 | v2.51.8 之前，目标语言包里这条已是中文时写回会退到「按行号兜底」，挑中这一行第一个字面量 —— 也就是查表键，`LocKey#` 引用当场全断（Pax Grips 的 4 条说明坏了 3 条）。现在兜底索引里不含语言包的键，一行只剩键时报「这一行只剩查表键, 写进去会打断本地化引用」；已坏的键要手动改回英文键（`SenSen` 那三个文件已就地修好） |
| 说明文字末尾挂着一串 `</>` | v2.51.8 之前补 `<Rich …>` 时按原文的关闭标记个数硬补。现在只补到开标签配平，译文自带的 `</>` 也会删掉 |
| 某行报「译文里同一段连写了多遍（模型跑飞），先确认再写」 | 模型把一句话连写了几十遍（记忆里实测 42/33/166 遍）。这类译文写回去不只是难看，`%s` 参数不够还会 `format` 崩，而且会被记忆反复复用。现在按软失败拦下；手改这一行或「↻ 重译」即可，坏记忆条目已被自动清掉 |
| 某行报「译文里的占位符比原文多出好几个」 | 译文凭空多出一串 `%s` / `{int_0}`，写回后 `format` 参数不够会崩。按提示改回与原文同数量的占位符 |

## 12. 已知限制

- 只做**文本**：贴图、音频、字体不处理。
- tweakdb yaml 只覆盖 `r6/tweaks` 下 `localized*` 字段的**行内引号标量**：块标量
  （`localizedDescription: |`）和 `displayName:` / `localizedDescription:` 里存的
  查表键不处理（后者的译文在归档或语言包里）。
- 归档层依赖 WolvenKit CLI，版本差异会影响组包。
- 官方语料只有 en→zh 一种方向；目标语言不是简体中文时官方基线不参与。
- 「快照式」部署：只覆盖，不删除。副本里删掉的文件不会从模组里消失。
- 单个英文标签上下文不足时（如 `Paint`），模型给的是通用词，不一定是行话。
- 返回值不是「菜单标题」的标签仍可能漏收：例如 NCPD First Response 的
  `groupOf()` 返回 `'MaxTac'` / `'Bikes'` 当车辆分组头，既不是 `label =`、
  也不是 `return "…", opts`，位置证据为零，只有四词以上的才落进长句兜底。
- 对话框内菜单 `add(label, fn)` 的短标签同样漏收（与 `safeCall` 形状相同，
  分开它们要看函数体，见 `docs/backlog.md`）。
