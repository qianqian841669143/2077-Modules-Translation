# 游戏内模组文本覆盖：方案对比与路线（2026-11-20 21:5x）

> 状态：**只做记录，本次没有改任何代码、任何 zip、任何游戏目录文件。**
> 触发：用户问「有没有更好的对游戏内模组文本的覆盖方法？」→ 选择「先写成 MD」。

---

## 1. 结论（先看这段）

1. **架构不用换**。现在这套是「显示层词典替换」，位置是对的：不动模组源文件、不动 `sourceId`、不受 Vortex 重部署影响。换成任何更底层的钩子都不会更省事。
2. **要换的是两件事**：
   - 词典从哪来（现在是「扫源码猜」，应改成「界面实际出现了什么就翻什么」）；
   - 拦在哪几层（现在漏掉 select 下拉选项、ImGui 数组参数、拼接串）。
3. 覆盖率 100% 的方法只有一个——静态改模组源文件，但它每次模组更新都要重跑、且和 Vortex 硬链接冲突，属于「一次性/离线」路线，不适合长期挂着。
4. **不存在「换一个更底层的钩子就一次性全覆盖」**：MCM 里的文字是 Lua 表里的裸字符串，既不经过本地化表，也不经过 ink 控件。见第 6 节。

## 3. 三处结构性漏点（有代码行号，可直接核）

### 3.1 select 下拉选项整类没翻 ★最高收益

三个 bridge 都会把选项文案放进 `setting.elements`（字符串数组），且 `type = "select"`：

- `ModConfigurationMenuAPI\bridges\ms\provider.lua:207-213`
  `setting.type = "select"`；`setting.elements[index] = localize(display)`
- `...\native_settings\provider.lua:703-705`
  `setting.type = "select"`；`setting.elements = localizedElements(option.elements)`
- `...\rcf\provider.lua:319-321`
  `setting.type = "select"`；`setting.elements = stringArray(row.options)`

而 `init.lua:278-332` 的 `patchSchema` 只碰 `name` / `cat.name` / `item.label` / `item.description`。

**后果**：「质量等级 / 单位 / 模式 / 刷新频率」这类下拉框现在必然全英文，而且三个 bridge 一处修好就全覆盖。
**改法**：在 `item.label` 之后遍历 `item.elements`（注意是数组，值就是显示串）。
**风险**：极低。`elements` 只用于显示，值本身（索引）不动，预设/集合/快照不受影响。

### 3.2 ImGui 的表/数组参数与窗口标题

`imgui_hook.lua:199-205` 的白名单是 25 个「首参为字符串」的函数。漏的几类：

- `Combo(label, cur, items)` / `ListBox(label, cur, items)`：`items` 是**字符串数组**，直接翻不了（要按表逐项查，且不能改顺序/长度）
- `TableSetupColumn("表头")`：表头
- `SeparatorText` / `LabelText` / `TreeNodeEx` / `ProgressBar` 的覆盖文字：根本不在名单里
- `Begin("窗口标题")`：代码里**故意**没碰（:197-198 注释：「传的是 id，改了会串窗口」），代价是窗口标题永远英文

**注意**：`Begin` 的标题在 `##` 之前是纯显示文字，`##` 之后才是 id。已有 `tr()` 的 `##` 切分逻辑（:85-94），理论上能安全翻标题，但会让 ImGui 的窗口状态（位置/大小）按新标题重记一次——**需要实测一次**，别直接上。

### 3.3 拼接出来的字符串

`lookup` 是整串精确匹配（`init.lua:259-271`）。模组里常见的 `"Enabled: " .. name`、`"Value: " .. v .. " s"` 这类**永远查不到**。

**改法**：精确失败后做「词条级」替换——按长度倒序建短语表，对字符串做整词边界替换；或先剥离 `前缀: ` 再查。**风险**：中文与英文混排、以及短词误替换（如 `On`/`Off` 是连接件），必须设最小长度（≥4 字符）+ 边界条件，并在日志里记替换了哪条，便于回退。

### 3.4 附带的正确性问题：`globalMap` 后写覆盖

`init.lua:121` `globalMap[orig] = zh`——跨模组兜底表是**最后写入者赢**。两个模组有同一句英文但意思不同时，会串译，而且没人知道。

**改法**：`addEntry` 时统计同一 `orig` 出现过的不同 `zh` 数量；>1 就标记为「多义」，`lookup` 的全局兜底跳过它，只留 `bySource` 精确命中。这条几乎零成本、纯收益。

## 4. 方法论问题：31334 条 vs 真实的界面文本量

账本是**扫模组源码里的字符串字面量**得来的，包含大量永不上屏的东西：日志前缀、配置键名、内部枚举名、异常消息。

粗估真实 MCM 可显示文本量级 2k-4k 条（此前估过 2000-4000）。也就是说：

- 现在的命中率问题，不是「翻得不对」，而是**表里九成是死条目**，把真正的漏译淹掉了；
- 全量 `loadfile` 一个 4.2 MB 的 Lua chunk（启动时一次性），加上 `bySource` + `globalMap` 两份表，属于可优化但不紧急的开销；
- 更要紧的是：**没人知道漏了什么**。目前靠人工在游戏里逛菜单发现。

**方向**：把「猜」换成「观察」——见 5.C。

## 5. 方案对比

| 方法 | 能覆盖 | 成本 | 副作用 / 风险 | 和现状的关系 |
|---|---|---|---|---|
| **A. CET 运行时词典（现状）** | MCM 数据 + ImGui 直绘 | 低 | 漏译（见第 3 节）；改账本要重启游戏 | 主体，保留 |
| **B. A 深化：补 `elements` + 扩 ImGui 面 + 归一化** | 补上 A 的两处结构空白 | 低（各十几行） | 无 | 叠加在 A 上 |
| **C. 未命中回流（miss-harvest）** | 让词典只包含「真的会上屏的串」 | 中：运行时记未命中（限量/去重，按 sourceId 分文件），工具只翻这些，回填账本 | 无；日志需要限量与轮转 | 叠加 A/B，**方法论上最优** |
| **D. 静态改源文件（工具已有）** | 100%，含 HUD 提示、通知、物品名、任务文本 | 高：每次模组更新重跑；和 Vortex 硬链接打架（Vortex 从 staging 重新链接会盖回去） | 更新即失效；改坏就是启动崩溃 | 互斥路线，只适合「不再更新的老模组」或做离线补丁包 |
| **E. `.archive` 补 zh-cn 本地化表** | 走 loc key 的模组自建内容（物品名、任务、日志） | 高：要 WolvenKit 打 archive，且要验合并/覆盖优先级（**未实测**） | 可能与模组自身 archive 冲突 | 补充，不冲突 |
| **F. redscript `@wrapMethod` 拦 ink 文本** | 原生 UI 里的文本（HUD、通知、交互提示） | 高：要 redscript 编译，每次游戏更新重编 | 全游戏热路径，误伤面最大；**对 CET ImGui 完全无效** | 最后手段；只在确认「模组文本进了原生 UI」时做，且只作用于白名单词条 |

> 说明：`inkTextWidget.SetText` / `SetTextByLocKey` 的具体签名与是否适合挡在这一层，**本轮未验证**（没读红字脚本 API）。若真要上 F，先写一个只记日志、不改字的探针版，统计一天内命中量与耗时，再决定。

## 6. 为什么没有「一键全覆盖」的底层钩子

三条文本路径互不相通：

1. **MCM / nativeSettings**：模组在 Lua 或 redscript 里把裸字符串注册进来 → MCM 用 ImGui 画。文本只在 Lua 表里存在过，本地化表与 ink 控件都见不到。→ 只有 A/B 能拦。
2. **模组自绘 ImGui 页**（CTO、AMM 一类）：`ImGui.Text/Checkbox/...` 直接画 → 只有 ImGui 层能拦。（`imgui_hook.lua` 头注释举的就是 CTO：539 条译文在账本里、界面一个字不显示。）
3. **模组自建内容**（物品、任务、日志、HUD）：走 `.archive` 的 loc key → 只有 D 或 E 能拦。

所以「更好的方法」不是找更底层的一个钩子，而是**按文本路径分层拦，并且让词典由实测驱动**。

## 7. 推荐路线

### 第一步：小、确定、马上见效

1. `patchSchema` 补 `item.elements`（第 3.1 节）。**一处改，三个 bridge 全覆盖。**
2. **多义词降级**（第 3.4 节）。几行。
3. **热重载**：CET 里重读账本，不重启游戏。
   - 账本侧可行：`lookup` 是闭包，重新赋值 `bySource` / `globalMap` 这两个 upvalue 即可，`patchProvider` 的包装函数不用重装。
   - **但 ImGui 侧有个坑**：`memo` 是 `imgui_hook.lua` 返回函数里的局部表（:58），外部清不掉。想热重载又不重复包装，得让 `imgui_hook.lua` 额外导出 `reset()`，或者让安装函数幂等（检测 `__imguiHooked` 标记，只重设 memo）。**直接二次 `install()` 会包两层包装器**，别踩。
4. ImGui 面扩展：`Combo`/`ListBox` 的 items 数组、`TableSetupColumn`、`SeparatorText`、`LabelText`、`TreeNodeEx`。

### 第二步：把词典对准现实

5. **未命中回流**：`lookup` 返回 nil 时，按 `sourceId` 记一条 `{原文, 次数}` 到 `miss_<sourceId>.log`（限 200 条/模组、去重、进程内缓存），退出/热键时落盘。工具读这些文件只翻这些串，再回填账本。
   - 直接收益：账本能从 31k 瘦到真实量级；`globalMap` 串译风险跟着降；「还不知道漏了什么」变成一份可读清单。
6. **归一化匹配**：大小写、首尾空白、连续空白折叠、句尾 `.`/`:`/`。`、全角半角。现在 `imgui_hook.lua` 已经手工补了句尾标点两个方向（:101-122），说明这问题真实存在——应当做成通用层，而不是在 ImGui 里打补丁。

### 第三步：等第二步收敛后再决定要不要换层

7. `miss.log` 里出现「物品名/任务文本」→ 才考虑 E。
8. 出现「原生 UI 提示」→ 才考虑 F（先探针）。
9. 某模组确定不再更新、且文本量大 → 用 D 单独做离线补丁。

## 8. 硬约束（改之前必须记住的）

1. **绝不翻 `id` / `sourceId`**。MCM 的预设、集合、快照、收藏全按 `providerId + "\0" + sourceId` 存（MCM 配置里能看到 `ms:Combat Redefine`、`ms:DNR_ModName` 这类键）。翻了就全部失配。
2. **显示名也有例外**：`names.lua` 是人工表，优先级高于账本，不要被工具生成物覆盖。
3. **CET 的 io 沙箱只认裸相对路径**。`init.lua:88-95` 的注释是踩坑记录：带 `mods/` 前缀会被拒（`Tried to access invalid path`），`package.path` 实测为空串。别「优化」成绝对路径或 `require`。
4. **改账本要重启游戏**——除非第 7.3 步的热重载做完。README 里写的这句就是当前事实。
5. **目录名 `zzz_` 前缀不能去**：CET 按目录名字母序加载，必须排在 MCM 之后，patch provider 才轮得到。
6. **不要在游戏目录里改**：那是 Vortex 的部署产物；要改的是 `E:\Vortex Mods\CP2077 Localization Pack.zip`，改完由用户自己 Deploy。游戏目录里手改，下一次 Deploy 会被 staging 盖回去（11-20 02:19 的教训）。
7. `elements` 只是显示串，**不要**去改 `setting.value` / 索引，否则存档里的设置值会错位。

## 9. 本轮未验证的项（别当结论用）

- `.archive` 本地化表的**合并 vs 覆盖**优先级、以及中文游戏下模组只带 en-us 时的回退行为——要实测。
- redscript 拦 ink 文本的**可行性与开销**——没读 API，没做探针。
- 31334 条里**真正会上屏的比例**——没有数据；第 5.C 步能顺带量出来。
- `Begin` 标题翻译后 ImGui 窗口位置/大小是否重记——需实测一次。
- 三个 bridge 是否还有别的文本字段（`hint` / `placeholder` / 分组标题）——目前只核了 `label` / `description` / `name` / `elements`。
