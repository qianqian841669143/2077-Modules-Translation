# P8 精简误报：把「像文本的东西」挡在表格之外

v2.23 的这条线只做减法。不新增翻译能力，不动应用/回填链路，只回答一个问题：

> 600 多个 `.reds` / `.lua` 文件里，哪些字符串**看起来**是文本、实际上玩家永远看不到，
> 或者看到了也不该由译者动手？

答案分五类。前四类是纯噪音，第五类会**改坏模组**。

---

## 1. 现状：噪音长什么样

v2.22 之后，默认开关在 302 个模组上产出 **26,337 行**。逐文件看，几处明显不对
（规模一列混有「逐行统计」与「整文件/整表统计」，最后以第 6 节的总表为准）：

| 现象 | 例子 | 规模 |
|---|---|---|
| 图集清单 | `kb_a:64:64:0\|kb_b:32:32:1\|...`（一条 1799 字符） | 41 行 |
| 桥接函数签名 | `GarageCore.Economy.EconomyBridge::GetPool;String` | 125 行 |
| TweakDB 记录名 | `Items.tony_wet_t-shirt_red` | 40 行 |
| SQL 片段 | ` ORDER BY entity_name ASC`（前导空格让旧规则漏掉） | 10 行 |
| 调试 dump | `walk dist=%.1f busy=%.1f leashed=%d` | 十余行 |
| 多语言副本 | `[en_us][pl_pl]Tego właśnie chciałaś?`、`확인`、`LACK` | 765 行 |
| 语言包副本 | `GarageCoreLocalization_de.reds` 整份德语 | 452 行 |
| 双语数据表 | `["Wall Wood With Lines"]="墙木…"` 的 key | 1,028 行 |
| 一文件 19 种语言 | `JVF Localization.reds`（EN/RU/PL/AR/…/ZH） | 859 → **78** |

合计约 2,700 行，占全部产出的 **10%**。

## 2. 两条判定线：硬噪音与软噪音

见过一次误杀就会明白：**能不能过滤，取决于这条规则会不会杀掉真文本**，
而不是取决于这条规则能删多少行。

### 硬噪音 —— 任何档位都不收

`src/text_noise.py` 的 `hard_family()`。判定放在 `is_translatable()` 里，
所以语言包层、设置层、长句兜底档都生效，开「调试文本」也不放行。

| 家族 | 规则 | 备注 |
|---|---|---|
| 资源转储 | `\|` 分隔且 ≥2 段是 `key:value` | 不要求整串无空格，但出现空格就放弃 |
| 资源转储 | `name:w:h:flag` 图集条目 | 只认三段数字，`2026-10-31` 不会中 |
| 资源转储 | `路径 (计数)`，必须含 `/` 或 `\` | 早期版本误杀过 `the subscriptions are full (8)` |
| 记录名 | `Items.` / `Vehicle.` / `gamedata.` 等前缀 | 只认无空格的记录名 |
| 记录名 | `A.B::C;签名` | REDscript/Lua 桥接声明 |
| 技术串 | SQL 关键字必须写全 | 曾用宽松 `SELECT\s`，把 `Select Category` 删了一整批 |
| 技术串 | 去掉 `%s`/`{0}`/`\n` 后一个字母都不剩 | `/`、`€$`、`{drop_point}` |
| 技术串 | `key=value` 至少两组，且不含 `<` | 含 `<` 的是富文本，不是 dump |

**含中日韩文字一律豁免。** 这行判断写在所有硬规则之前——中文文本永远是目标文本，
不存在「技术串」的可能。

### 软噪音 —— 只在「长句兜底」这一档过滤

`soft_family()`。调用点只有两个：Lua 的兜底循环、REDscript 的 `plain` 证据分支。
开「调试文本」时全部保留。

| 家族 | 规则 |
|---|---|
| 外文表 | 以两个以上 `[xx_xx]` 语言标签开头 |
| 外文表 | 含西里尔/希腊/希伯来/阿拉伯/天城/泰/假名/谚文 |
| 外文表 | 含 ≥2 个有辨识度的变音符号（`żźćńółęąśčřšžďťňůěőűığş` + `äöüß` + `¿¡`） |

为什么不是硬规则：模组确实会把非英语标签写在控件上（`label("Standard")`），
那是玩家真会看到的一行字，删掉就是漏翻。而硬噪音不存在这种可能。

为什么要求「≥2 个变音符号」：`Álvarez`、`José` 这类人名只有一个重音，
一刀切会把西语/葡语人名全删了。两个以上才基本能确定是波兰语/捷克语/匈牙利语。

## 3. 双语数据表：误报里唯一会改坏模组的一类

AMM 的中文补充包长这样：

```lua
return {
["catalog"]={
["Wall Wood With Lines Long (With Collision)"]="有碰撞的长条木墙",
["Aaron McCarlson"]="亚伦·麦卡森",
},
}
```

左边是 AMM 代码里 `data.catalog["Wall Wood With Lines Long (With Collision)"]` 的**查表 key**，
右边才是给玩家看的字。提取器当时把 key 和 value 都收进了表：value 被目标语言过滤掉了，
key 留在「原文」列——1,028 行。

危险的不是多了一千行，而是**回填**：把 `["Wall Wood With Lines Long"]` 换成
`["有碰撞的长条木墙"]`，AMM 的查找立刻全部落空，摆件从列表里消失。

判定方式（`bilingual_keys()`）：整份文件里至少 30 组 `["英文"]="含中文"` 才算双语表，
返回 key 集合，提取时命中就跳过。阈值 30 是为了排除单条 `["x"]="y"` 的普通配置。

实测：该文件 1,217 → 181 行。

## 4. 一个文件装下十几种语言

`V Voice Framework/JVF Localization.reds` 有 19 个函数：

```redscript
func JVF_SubText_EN_US(ruid: Uint64) -> String { ... }
func JVF_SubText_RU_RU(ruid: Uint64) -> String { ... }
func JVF_SubText_ZH_CN(ruid: Uint64) -> String { ... }
```

同一个 `ruid` 在 19 段里各出现一次。v2.22 全部收下：859 行，其中只有 78 行是英文，
其余是俄语、波兰语、捷克语、阿拉伯语……把它们当「原文」送进中文表格毫无意义。

`lang_sections()` 认两种分段头：

- `func X_EN_US(` / `func Text_PL(` —— 函数名尾部语言码
- `class German extends ModLocalizationPackage` —— 语言包类名

出现**两种以上语言**才启动（单语言文件完全不受影响），保留 `EN` 那一段，
其余整段丢弃。没有英语段的纯外语包则一段都不留——把整份俄语包当原文翻一遍，
只是换个方式生产误报。

`DynamicEnemyMultiplier/Localization.reds` 是同一个问题的类写法
（`English` 类里放的是中文、`Russian` 类里放俄语），也从 118 行降到 78 行。

## 5. 语言包副本：文件名识别补了一个缺口

`is_locale_file()` 原本只认两种文件名：`de_de.reds` 这类**语言码当文件名**的，
和 `English.reds` 这类**语言名当文件名**的。漏掉了第三种：

```
GarageCoreLocalization_de.reds
GarageCoreLocalization_ko.reds
```

词干里带 `Localization`、尾部带 `_de` / `_ko`。它们于是被当普通源文件扫，
452 条德语/朝鲜语以「原文」身份进表。

新增规则：**词干以本地化字样结尾 + 语言后缀**（`localization` / `locales` /
`strings` / `i18n` / `l10n` / `texts` / `translations` + `_de` 等）。
全语料只有 4 个文件命中，全部是 Garage Core 的语言副本（`_de` / `_ko` / `_cn` / `_tw`），
没有波及任何正常文件。

`BoardEnglish.reds` 这类**没有语言后缀**的英语语言包不会被误判——它正是要翻的源文本。

## 6. 实测

302 个模组，默认开关（优先语言包 / Provider 配对 / .lua 设置文本 / 长句兜底 全开，
调试文本、语言包文件 关）：

| 模组 | v2.22 | v2.23 | 说明 |
|---|---|---|---|
| AMM CHS Translation Supplement | 1,217 | **181** | 双语表 key |
| V Voice Framework | 969 | **188** | 只留 EN 段 |
| Garage Core | 875 | **358** | 去掉 `_de` / `_ko` |
| GHXST Companion | 1,591 | 1,514 | 77 条图集清单 |
| DynamicEnemyMultiplier | 118 | 78 | 俄语段 |
| MBC / MCM / ACM / CP2077 等 | — | 不变 | 没有被误伤 |
| **总计** | **26,337** | **23,679** | **−10.1%** |

两条不变式：

- 没有任何模组**变多**（0 个）；
- 没有任何模组**清零**（0 个）。

逐行比对 2,658 行被删的行，全部落在五类里。唯一看起来像英文正文的两条
（`Kaukaz Bratsk with Trailer`、`At Your Own Risk`）查了原文，是 AMM 双语表里
自己没翻的 key：

```lua
["Kaukaz Bratsk with Trailer"]="Kaukaz Bratsk with Trailer",
["At Your Own Risk"]="实验角色（可能异常）",
```

## 7. 可视化

过滤是**可见**的，不是无声消失：

- 工具栏右侧：`已过滤噪音 1,783 条：外文表 1,783`（V Voice Framework）／
  `已过滤噪音 1,028 条：双语表 1,028`（AMM CHS Translation Supplement）
- 扫描报告多一段：按家族列出条数
- `meta["noise"]` 随 `load_mod` 一起返回，前端直接读

想看全量：勾上「调试文本」，软噪音（外文表）不再丢；硬噪音仍然不出现——
它们不是文本，给译者看也没有意义。

## 9. 下次再加规则时

1. **先量再做**：把 `extract_root_ex` 的结果导成 TSV，按家族分组看样本，
   不要凭印象写正则。
2. **先查召回**：新规则写完，把被删的行全部打印出来读一遍。上面每一条规则
   都至少误杀过一次真文本（`Select Category` / `Base: ` / `the subscriptions are full (8)`）,
   才发现问题。
3. **硬或软，看误杀代价**：删错的代价是漏翻，宁可不删——所以语言相关的一律归软。
4. **加断言**：`tools/selftest.py::check_noise_rules` 里一条 `assert` 比注释管用。
