# P7 应用到模组：现有实现细节

这份文档记录 v2.22 里「应用到模组」这条链路的**当前真实行为**，用来对照后续改动。
不是设计提案，也没有新功能。

链路：

```
表格行 ──applyAll()──▶ Api.apply(items) ──线程──▶ _do_apply / _apply_resource
                                                  ├─ locale_pack   写回语言包
                                                  ├─ mod_text_engine 写回源码字面量
                                                  ├─ undo_store    撤销快照
                                                  └─ localization.builder / verifier 组包
```

## 一句话

同一个按钮，两种语义：源码模式**原地改写** mod 里的 `.json/.reds/.lua`；资源模式**不碰原 mod**，
只把改动过的 CR2W 条目打成新的 `.archive` + `.archive.xl`。

## 1. 两种模式

按钮是 `#btn-apply`，文案由 `applyModeUi()` 按当前模式切换（`web/app.js`、`web/index.html`）。

| 模式 | 按钮文案 | 实际动作 | 原 mod 是否被改 |
|---|---|---|---|
| 源码模式 `content` | 应用到模组 | 原地改写 `.json/.reds/.lua` | 是（有 `.bak` + 可撤销） |
| 资源模式 `resource` | 生成翻译 mod | 从 `.archive` 解出的 CR2W 里只取改动条目，组新归档 | 否，一个字节都不动 |

确认框文案跟着变：

- 源码模式：`将把 %d 条译文写回模组源文件 %s（自动创建 .bak 备份，可随时恢复）`
- 资源模式：`将把 %d 条译文打包成一个新的翻译 mod。原 mod 不会被修改，产物输出到输出目录。`

资源模式下「撤销上次应用」按钮直接隐藏（`applyModeUi()` 里 `display:none`）——没有写回，也就没有可撤销的东西。

## 2. 哪些行会被写

`applyAll()`（`web/app.js`）：

```js
expandRows(state.rows).forEach(r => {
  if (!r.trans || r.trans === r.orig || r.skip) return;
  items.push({root, file: r.file, line: r.line, orig: r.orig, trans: r.trans,
              target: r.target || "", kind: r.kind || "", key: r.key || ""});
});
```

三条硬规则：

| 规则 | 含义 |
|---|---|
| 译文为空 → 跳过 | 没填的行不写，也不占位 |
| 译文 === 原文 → 跳过 | 防止把英文「译」回英文时反而改坏格式 |
| `skip` 勾选 → 跳过 | 表格「跳过」列；导出/导入 Excel 时 `skip` 同步往返 |
| `dups` 展开 | 合并重复行显示时是一行，写回时按 `dups` 逐条展开，一条不漏 |

`items` 就是前后端契约：

| 字段 | 用途 |
|---|---|
| `root` | mod 根目录（取 `items[0].root`，缺省 `self.root`） |
| `file` | 源文件相对路径 |
| `line` | 源文件行号 |
| `orig` | 原文（用于二次匹配） |
| `trans` | 译文 |
| `target` | 目标语言文件相对路径（空表示就地改） |
| `kind` | `json` / `text` / `resource` |
| `key` | JSON 的键路径 |

`Api.apply()` 立即返回 `{ok:true, started:true}`，真正的写在后台线程，结果通过 `applied` / `error`
事件回推；`_busy` 做互斥，忙时返回 `{"error":"busy"}`。

## 3. 源码模式：`_do_apply`

入口 `web_app.py` 的 `Api._do_apply()`。开头先做一次分流：

```python
if any((it.get("kind") or "") == "resource" for it in items):
    return self._apply_resource(items)
```

**只要有一行是 resource，整批都走资源模式**（不会混着写）。之后按 `(file, target)` 分成两组：
`json_groups` 先处理，`text_groups` 后处理。

### 3.1 JSON 组

`locale_pack.write_json_target_ex(root, src, tgt, mapping)`：

- 以**源** JSON 为底稿读出整棵树，写进**目标** JSON —— 目标文件不存在时会自动生成；
- 键写入两种方式：扁平结构（键本身就带点，如 MCM 的 `settings.section.access`）直接
  `data[key] = val`；否则按点路径 `_set_path()` 逐级下钻；
- 落盘 `json.dump(indent=2, ensure_ascii=False)`；
- 找不到的 key 计入失败，原因 `目标 JSON 中找不到对应 key`。

### 3.2 文本组（`.reds` / `.lua`）

每组依次做五件事：

| 步骤 | 实现 | 说明 |
|---|---|---|
| 1. 撤销快照 | `snapshot(dst)` / `snapshot(dst + ".bak")` | 同一个事务内去重，只存第一次 |
| 2. 生成目标文件 | `locale_pack.ensure_target()` | `tgt != src` 且目标不存在 → **从源文件复制**一份，记进 `created` |
| 3. `.bak` | `E.backup_file()` | 已存在则不覆盖（只保留**最初**内容） |
| 4. Codeware 注册 | `locale_pack.prepare_codeware_package()` | 仅当 `tgt != src` 且目标是 `.reds` |
| 5. 写字面量 | `E.apply_many_ex(dst, pairs)` | 一次读、一次写 |

第 2 步的后果值得记住：**复制出来的目标文件是英文原件**，只有命中的条目被替换，
没提取到的行仍然是英文，这个半成品在游戏里就是中英混排。

### 3.3 三级匹配（`apply_many_ex`）

写回最容易在这里翻车，所以是三级兜底：

| 级别 | 匹配键 | 适用场景 |
|---|---|---|
| 1 | `(行号, 可见文本)` | 常规，最精确 |
| 2 | `可见文本` | 目标文件排版/行号与源文件不同 |
| 3 | `行号` | 原文本身被改过，按该行尚未使用的字面量顺序取 |

细节：

- 三级查找都从候选列表里 `pop`，`used` 集合按字符 `start` 去重，**同一个字面量不会被两条译文改两次**；
- 替换**按位置降序**进行，避免前面的替换让后面的偏移失效；
- Codeware 的 `"text##id"` 隐藏后缀会被保留：`suffix = lit.inner[len(orig):]`，拼接后再
  `escape_for()` 转义引号与反斜杠；
- 三级全落空 → 记失败明细 `未找到对应原文`，不写文件。

### 3.4 Codeware 语言包自动注册

`prepare_codeware_package()` 在**复制出来的目标 `.reds`** 上做两件事：

1. 把目标文件里 `class X extends ModLocalizationPackage` 的类名从 `English` 改成
   `ChineseSimplified`（不改会报 REDscript `SYM_REDEFINITION`）；
2. 在匹配的 `ModLocalizationProvider` 里补 `import` 和
   `case n"zh-cn": return new ChineseSimplified();`。

Provider 不是靠猜的：提取阶段 `discover_provider_pairs()` 已经按「case 返回的类名 → module/import →
实际语言包文件」解析出精确的 `providers` 列表，写回时用 `provider_rels` 锁定，找不到就报错而不是乱改。

先校验后写入：指定了 Provider 但文件不存在 / 不是 `ModLocalizationProvider` / 没有可插入的
`switch/default` 分支，都会直接返回 `error`，**不会留下半完成状态**。

### 3.5 返回体

```python
{"ok": n, "fail": m, "errors": [...][:20], "created": [...], "providers": [...],
 "undoId": "...", "undoAvailable": bool, "failed": [...][:2000], "failedTotal": N}
```

前端 `onApplied()`：

- `created` 非空 → toast「已生成 N 个语言包文件」
- `providers` 非空 → toast「已自动注册 N 个语言加载入口」
- 有失败 → 弹模态框列明细（文件:行号 / 原文 / 译文 / 原因，可一键复制）
- 全成功 → 「N 条译文已写回模组。Vortex 用户请重新 Deploy 后启动游戏。」

## 4. 备份与撤销：两层，别混

| 机制 | 位置 | 生命周期 | 粒度 |
|---|---|---|---|
| `.bak` | 源文件旁边 | 永久，**只保存第一次应用前的内容**（已存在则不覆盖） | 每个文件一份 |
| 撤销事务 | `%config%/undo/<时间戳-id>/files/*.bin` + `manifest.json` | 每个 mod 目录保留最近 **30** 次，超出按 `created_ns` 清理 | 每次 apply 一份完整快照 |

`ApplyTransaction.snapshot(path)`：

- 只快照 **mod 根目录下**的路径（`_inside()` 校验，防越界），越界直接返回 `False`；
- 同一路径重复调用只存第一次（`_seen`）；
- 记录 `existed` 标志——原本不存在的文件回退时是**删除**而不是还原。

`commit()` 时如果一个文件都没快照 → 直接 `discard()`，不产生空记录。

`undo_last(root)`：

- 取该 `root` 最近一次事务（按 `created_ns` 排序，不是按 id 字符串比）；
- 原本存在 → 从快照还原；原本不存在（本次新建的语言包）→ 删除；
- **只有全部成功才删事务目录**，有失败则保留记录供重试，返回
  `{ok:false, error:"撤销未完全成功", restored, deleted, errors}`；
- 前端 `undoLastApply()` 先 `undo_status(root)` 显示「时间 + 将恢复 N 个文件」，确认后异步执行。

`_prune()` 按**规范化的 root 分组**各自保留 30 次，不是全局 30 次。

## 5. 资源模式：`_apply_resource`

语义完全不同：不写回，只出包。

```
sess.apply_rows(items)          # 按 (rel, entryId) 把译文写进内存里的 CR2W doc
  → sess.build(outdir)          # 只取「真正改过的条目」组 spec
  → WolvenKit serialize → pack
  → <outdir>/<name>.archive + <name>.archive.xl
  → verifier.verify_build()     # report{ok, problems, warnings} → canInstall
```

关键约束：

| 约束 | 原因 |
|---|---|
| **只带改动条目** | `changed()` 以 `set_text()` 实际写过的 `(rel, entryId)` 为准（不看 UI 行对象，那是另一批对象），再 `_partial_doc()` 裁子集；几百 KB 而不是几 MB |
| **必须换命名空间** | onscreen 资源写到 `_out_rel(target.name, lang, rel, idx)`。沿用原路径（如 `quickhack_fixes\localization\en-us.json`）会让我们的中文归档遮蔽原 mod 的同名英文资源，而只带改动条目会导致其余文本整段消失 |
| **字幕要成对** | `.xl` 指向注册表（`SubtitleMap`）而不是文本（`entries`），`SubtitlePair.ensure_map_points_here()` 负责把 map 指向自己的 entries |
| **声明与内容交叉校验** | `.xl` 按 `onscreens/lipmaps/vomaps/subtitles` + 语言段声明，再互查「声明了没打包」「打包了没声明」，进 `warnings` |

`apply_rows()` 只认 `kind` 为空或 `resource` 的行，且译文 `strip()` 后必须非空。

安装/卸载是两个独立动作，都不碰原 mod：

- `install()`：只写 `archive\pc\mod` 下两个文件（`<name>.archive` / `<name>.archive.xl`），同名已存在先 `.bak` 一份；
- `uninstall()`：删那两个（连 `.bak` 一起），返回删掉的列表。

## 6. 批量队列是第三条路

`queue_start()` 不复用表格会话：队列自己开 `Session`、自己填译（记忆库 → 官方双语库 → 本地模型）、
自己 `build`，结果**只写输出目录，既不写回也不安装**。

版本迁移靠 `batch/state.json` 里 per-mod 的 `entryId` 快照——mod 更新后没变的条目直接复用旧译文，
只翻新增/改动的。

## 7. 边界与坑

1. **生成的目标文件是英文原件**：`ensure_target` 复制源文件，之后只替换命中条目。没提取到的行仍是英文。
2. **`.bak` 不是「上一次」而是「第一次」**。同一文件多次应用后 `.bak` 永远是最初内容，中间态只能靠撤销事务找回。
3. **撤销只认 `root` 完全一致**（`_norm` 比绝对路径）。换盘符、改大小写、移动目录后旧记录就找不到了。
4. **Vortex 场景下写回不等于生效**：写的是 `E:\Vortex Mods\...` 这类 installed/staging 目录时，游戏里跑的是 Deploy 出来的副本，UI 只有一句 toast 提示重新 Deploy。
5. **行号会漂移**：在上方插入一行，后面所有行号失配，只能靠第 2/3 级兜底。若同文件有大量相同短文本（`"OK"`、`"Yes"`），第 3 级可能替错位置——`used` 集合能防重复，防不了换行。
6. **JSON 目标文件被整体重写**：注释、键顺序、原有缩进风格都会丢（只保证 `indent=2`）。MCM 那种几千键的扁平大 json 尤其明显。
7. **资源模式前提很硬**：必须有游戏目录 + WolvenKit CLI + `canInstall`，否则只能生成不能装。

## 8. 对当前 302 个模组语料的适用性

拿 `E:\Vortex Mods\cyberpunk2077`（302 个 mod / 5,566 个文件 / 11.1 GB）实测的结果：

| 现象 | 数字 | 对这条链路的影响 |
|---|---|---|
| 松散 `localization/*.json` | **0 个** | JSON 组那条分支几乎用不上（`_set_path` / 扁平 key 逻辑基本空转） |
| `.reds` | 1,982 个，分布在 159 个 mod | 主战场：文本组 + 三级匹配 + Codeware 注册 |
| `.lua` | 942 个，分布在 76 个 mod | 文本组，绝大多数是 CET 设置界面 |
| `.xl` 里的文本指令 | 232 个文件，`MergeTextEntry` / `MergeSubtitleResource` / `localizationPersistence` **0 处** | 资源模式（组归档、字幕配对、`.xl` 声明）在这批语料上基本无事可做 |
| `.archive` | 292 个 / 10.3 GB (93% 体积) | 大多是纯资源包（模型、贴图），不含可翻译文本 |

结论：这条链路真正吃成本、也真正可能出错的地方是两处——

1. `.reds` 语言包能不能配对到正确的 Provider（配错就整组失败或改错文件）；
2. 长句兜底那 15,188 条误报（资源路径、TweakDB 记录名、日志模板）会不会被当成译文写进文件。

第 2 点尤其要注意：写回是**不可逆地改源文件**（有 `.bak`，但 `.bak` 只留第一次），
误报一旦落盘，需要靠撤销事务或重新下载 mod 才能清干净。
