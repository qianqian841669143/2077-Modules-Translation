## 实证结论（这是 M1 编码的依据）

### 1. onscreens —— 已完全跑通

- 归档内资源必须是 **CR2W**，root chunk 的 data `$type` = `localizationPersistenceOnScreenEntries`。
- 条目结构：`{primaryKey, secondaryKey, femaleVariant, maleVariant}`。
- `.xl` 写法（路径**相对归档根**，反斜杠）：

```yaml
localization:
  onscreens:
    zh-cn:
      - localization\zh-cn\onscreens.json
```

- 合并语义：按 `primaryKey` **原地替换**，所以替换官方文本会立刻生效（已肉眼验证）。
- 路径任意，不必模仿官方 `base\localization\...` 结构。

### 2. subtitles —— 机制与原先设想不同，但已跑通

**关键纠正**：`subtitles:` 指向的不是文本文件，而是一份**字幕文件注册表**
（`localizationPersistenceSubtitleMap`）。游戏按注册表再去加载真正的文本文件。

因此一次字幕注入需要**两个**资源：

| 角色 | `$type` | 条目结构 |
|---|---|---|
| 注册表（`.xl` 指向它） | `localizationPersistenceSubtitleMap` | `{subtitleFile, subtitleGroup}` |
| 文本（注册表指向它） | `localizationPersistenceSubtitleEntries` | `{stringId, femaleVariant, maleVariant}` |

`subtitleFile` 是**资源引用对象**，路径在 `DepotPath.$value` 里：

```json
"subtitleFile": {
  "DepotPath": {
    "$type": "ResourcePath",
    "$storage": "string",
    "$value": "localization\\zh-cn\\subtitles\\m0sub_text.json"
  },
  "Flags": "Soft"
}
```

`.xl` 写法：

```yaml
localization:
  subtitles:
    zh-cn:
      - localization\zh-cn\subtitles\m0sub_map.json
```

- `subtitleGroup` 用现成的组名（如 `quest`、`open_world`），别自己编。
- ArchiveXL 的做法是把 map 条目 **PushBack** 进该语言的字幕表，再由游戏加载我们的文本文件。

### 3. 三个会导致「日志报错 / 静默失败」的坑

| 坑 | 现象 | 修法 |
|---|---|---|
| 把 Entries 文件直接塞给 `subtitles:` | `Resource "..." failed to load.` | 必须给 Map |
| 把路径写进 `subtitleFile.$value` | WolvenKit 报 `JSON value could not be converted to RedFileDto` | 写到 `DepotPath.$value` |
| `.xl` 放在被 pack 的目录里 | pack 警告 `Unknown file extension`，虽被跳过但不干净 | `.xl` 放打包目录之外 |

### 4. WolvenKit CLI 用法（9.1.0 实测）

```powershell
WolvenKit.CLI.exe unbundle   <archive> -o <dir> -v Minimal
WolvenKit.CLI.exe convert serialize   <cr2w.json>   -o <dir>
WolvenKit.CLI.exe convert deserialize <x.json.json> -o <dir>
WolvenKit.CLI.exe pack <dir> -o <outdir>
```

- `-o` 目录**必须已存在**，否则报 `Invalid output directory`。
- `pack` 把目录**内容**打包，输出名 = 目录名（`m0test\` → `m0test.archive`）。
- 用 Python `json.loads` → 改 → `json.dumps(indent=2)` 往返是安全的，WolvenKit 能吃回去。

## 留给 M1 的问题

1. **字幕是追加还是替换？** 源码是 `PushBack`，我们的条目排在官方之后。
   已由 P5 实测回答：**后者胜**，我们的条目会覆盖同 `stringId` 的原文，
   差异式归档对字幕成立。详见 `P5字幕覆盖.md`。
2. **一个 mod 多个字幕文件**时要生成多个 map 条目（一个文件一条），不是一个大文件。
3. 字幕的 `stringId` 是数字串，跨语言一致，所以 en→zh 对齐靠它，不靠文本匹配 ——
   这对官方双语语料建 TM 是好消息。

## 若失败，按现象排查

| 现象 | 可能原因 |
|---|---|
| `unbundle` 报错 | 命令名在旧版是 `extract`，脚本已自动回退 |
| 归档装上后毫无变化 | ArchiveXL 未装 / `.xl` 与归档不同名 |
| `Resource "..." failed to load` | `.xl` 里路径与归档内路径不一致，或资源类型不对 |
| 日志里没有 Localization 段 | ArchiveXL 版本过旧 |
| 主菜单变了但字幕没变 | 追加而非替换，预期行为，见上 |
