# P9 · Vortex 活动映射与翻译失败回执（v2.24）

## 一、问题：三分之一的工作量是白做的

工具从 v1.x 起就假设「安装缓存目录下的每个子目录 = 一个在用的模组」。这个假设在
Vortex + 硬链接部署下不成立。

实测这台机器：

| 项 | 数量 |
|---|---|
| 安装缓存目录（`E:\Vortex Mods\cyberpunk2077`）里的子目录 | 302 |
| 部署清单里真正被引用的来源目录 | **194** |
| 只有目录、没有部署的 | **108**（35.8%） |
| 下载包（`E:\VortexDownloads\cyberpunk2077`） | 289（259 zip / 16 rar / 14 7z） |

那 108 个不是垃圾：Vortex 更新模组时会**新建**一个目录（名字带新版本），旧目录留在
原地不删。它们里面是完整的旧版文本，提取出来照样进表格、照样被翻译、照样占翻译记忆，
但游戏一个字节都读不到。

所以 v2.23 那份「302 个模组 / 23,679 行」的实测口径本身是偏大的。

## 二、事实基础：三条链路，都能验证

### 1. 下载包是只读的版本锚

Nexus 的包名自带 `modId` 和版本，且下载后不会变。两种命名格式并存：

```
Title-27505-2-0-1773756783.zip                          # Nexus 经典
ArchiveXL 4198 1.28.6 2026-10-29T12-59Z VquAqYEdu.zip   # Nexus 新版
```

### 2. 缓存目录名 = 压缩包名去扩展名

Vortex 用包名建目录，所以两层可以直接对齐。实测 273 个 modId 两边都有，
**0 个下载包找不到安装位置**。

### 3. `vortex.deployment.msgpack` 是权威的「谁在生效」

`<安装缓存>\vortex.deployment.msgpack`，msgpack 格式，每次 Deploy 重写。字段：

| 字段 | 实测值 |
|---|---|
| `deploymentMethod` | `hardlink_activator` |
| `stagingPath` / `targetPath` | `E:\Vortex Mods\cyberpunk2077` / `…\Cyberpunk 2077` |
| `deploymentTime` | 毫秒时间戳（截图时是 11 分钟前那次部署） |
| `files` | 1833 条 `{relPath, source, target, time}` |

`files[].source` 是缓存目录名，`relPath` 是游戏内相对路径。**194 个 source 全部能在
缓存里找到对应目录，0 条断链**。所以「目录在不在清单里」可以直接当生效判据。

`target` 字段实测全是空串，不要依赖它，游戏路径用 `targetPath + relPath` 拼。

### 4. 硬链接意味着改缓存 = 改游戏

```
fsutil hardlink list "…\Cyberpunk 2077\archive\pc\mod\Universal_AI_V_Voice_Swap_Compatibilityvv.archive"
→ \Vortex Mods\cyberpunk2077\…\archive\pc\mod\…  （同一个 inode）
→ \SteamLibrary\steamapps\common\Cyberpunk 2077\…
```

于是各操作对译文的影响是：

| 操作 | 存在缓存里的译文 |
|---|---|
| 工具写回缓存文件 | 立刻等于改了游戏文件（无隔离，但立即生效） |
| Vortex purge（撤销部署） | 保留（只删游戏侧链接） |
| Vortex deploy | 保留（从缓存重建链接） |
| **Vortex 更新模组** | **丢失**（旧目录被删，新目录解压覆盖） |
| 卸载模组 | 丢失 |

也就是说日常 purge/deploy 是安全的，只有「更新/卸载」会吃掉译文——而这恰好是最常见
的场景。这也是「译文最好别只存在缓存文件里，要有一份按原文指纹索引的仓库」的直接理由
（映射表就是那份仓库的坐标系，见第四节）。

## 三、实现

新增 `src/vortex_map.py`（只读，不碰 Vortex 任何状态）：

- **自带 msgpack 解码器**。不引第三方依赖，单文件 exe 不用多打包一个库。
  支持 map/array/str/bin/int/float/bool/nil，完整解码 291,862 字节的清单。
- **名字解析**四种格式：新版空格格式、经典短横格式（版本段允许字母，如 `v1-0-0`、
  `PL-Beta-1-8-8-Hotfix`）、无时间戳的中缀格式、纯 `Title 12345 1.2.3`。
  实测 302 个目录 + 289 个包**全部可解析，0 个 unparsed**。
- **版本归一化**：`2-8-1` / `2.8.1` / `v2.8.1` / `1.0.0` 归一成同一串；归一后再取数字
  元组比大小，用来判断「下载包是不是比装的新」。拿不到数字就不猜。
- **分档**（优先级从上到下）：

  | 状态 | 判据 |
  |---|---|
  | 合集 | 目录名 `vortex_collection_*` |
  | 生效 | 在清单里，版本一致 |
  | 有更新待装 | 在清单里，下载包版本更新 |
  | 版本不一致 | 在清单里，版本不同但比不出大小 |
  | 新版未部署 | 不在清单里、下载包更新、且同 modId 没有生效目录 |
  | 陈旧未生效 | 不在清单里、有下载包 |
  | 无下载包 | 不在清单里、也没有下载包（手动安装） |

- **自动探测目录**：从 `%APPDATA%\Vortex\vortex*.log` 尾部捞
  `{"stagingPath":…,"gamePath":…}` 与 `"archivePath":…`，再用「该目录里是否真有
  `vortex.deployment.msgpack`」验一遍；都不中才按常见布局（`<盘>:\Vortex Mods\cyberpunk2077`
  等）兜底。

界面侧：

- 设置 → 新增「安装缓存 / 下载包」两个目录 + 浏览 + 自动探测 + 扫描活动映射 +
  「加载时提示该目录是否生效」开关。
- 「更多 → 活动映射…」打开面板：环境行、状态筛选、搜索、表格（状态/模组/ID/已安装/
  下载包/文件数）、点一行填路径、双击加载、复制清单 TSV。
- `_do_load` 返回 `mapState`，状态栏写明「已生效（22 个文件，2026-10-31 06:34 部署）」
  或「未生效：该目录不在 Vortex 部署清单里」。


## 五、翻译失败回执

`Api._trans_report(targets, reasons, stopped, memory)` 在每个退出路径都会调一次
（正常结束、接口报错、手动停止），推一条 `trans-report` 事件：

```json
{"type":"trans-report","total":1330,"ok":1287,"left":43,
 "failed":[3,9,11,…],"memory":402,"stopped":false,
 "reasons":["调用本地模型失败：HTTP 500 - internal server error",
            "模型返回了空译文（7 条）"]}
```

前端 `onTransReport` 渲染成最上层提示（`.mask.top`，`z-index: 300`）：

- 四个数字块：已翻译 / 未翻译 / 来自记忆 / 本次合计；
- 失败原因逐条列出；
- **继续翻译剩下的** → 用 `failed` 里的行号再调一次 `translate(indices)`，只补这些；
- **确认** → 关闭并重绘表格。

「没翻出来」的判据是**译文为空**，不是「抛了异常」。模型偶尔返回空串，以前算成功，
表格里留一行空白还没人知道。

只在 `left > 0` 或 `stopped` 时才弹窗，全成功仍然只走状态栏，不打扰。

## 六、边界

- **清单会变**。它反映 Vortex 当前状态（实测截图那次是 11 分钟前写的）。界面每次扫描
  重读，不用缓存当配置。
- **`.7z` / `.rar`（共 30 个）不读内容**，只用文件名做版本锚，所以不需要解压器。
- **6 个 modId 没有下载包**（107 / 33737 / 34861 / 35136 / 35625 / 5266），是手动安装
  或别的来源，没有版本锚，只能按目录名兜底。
- **版本比大小对非数字版本不可靠**（`0.3.0-pre.5`）。比不出来就退到「版本不一致」，
  不硬猜。
- **只读**。工具不写 Vortex 的清单，也不改它的数据库；Vortex 开着时读清单是安全的。

## 七、自测

`tools/selftest.py` 新增两项：

- `check_vortex_map()`：四种命名的解析、版本归一（含 `2-8-1 ↔ 2.8.1`、`1.0 ↔ 1.0.0`、
  `2.3 ≢ 2.3.1`）、自造 msgpack 清单验证 `source` 归并、临时目录里造「生效 / 陈旧 /
  合集」三种目录并断言分档与统计。
- `check_translate_report()`：接口抛错时应给出 `left == 3` 与原因；模型返回空串时应
  给出 `ok == 1 / left == 2` 且 `failed == [1, 2]`。

界面用 CDP 截图脚本验证（`build/v224_smoke.py` + `build/cdp_shot.ps1`），确认
弹窗打开、`z-index: 300`、计数正确、无 JS 报错。
